## 1. 第 1 章 · 立论：AI Agent 时代的研发次序（重大发现/思路）

**一句话命题**
> 在 Agent 时代，人的价值从「写算子」上移到「写约束」；Agent 的价值从「替你判断」下沉到「替你执行可判定的事」。因此第一性工程不是先搭智能体，而是**先用 Agent 把算子、求解器这类确定性资产研发出来并冻结**，再把协作、计算、调度、发现交给 Agent。

建议给这个思路一个可引用的名字：**「确定性底座优先」（Determinism-first）**，副题「先冻结算子，再放 Agent 去发现」。

**三条支撑命题（逐条给反例与本例证据）**

1. **判断不可外包，判定可以外包。**
   Agent 不擅长回答「这个结论可信吗」，但擅长「在给定判据下跑 86 批、逐位比对、把结果结构化落盘」。本例：493 个 `tools/rNNN_*.py` 探针，绝大多数是一次性、只读、零引擎改动的确定性任务；幂等治理文本 46 项精确替换、三次复跑零写入；所有治理数字从 `runs/` 读取而非模型生成。
2. **探索必须有锚，否则「发现」无法与「漂移」区分。**
   反面证据：闭环数据同化让产量从 86/86 掉到 **6/86**、49/86 批产素归零；V2 八路扰动方差注入 **18/20 NO_GO**、样本外 seed 11 崩到 **99.85 pp**；恒真判据 D-38（86/86 全报 normal 的「0 catastrophic」从未检验任何东西）与 D-78（覆盖率 0.899548532731377 对零信息常数预测器逐位相同）说明没有冻结判据时，Agent 连「自己错了」都测不出来。
   正面证据：86 批逐位零回归 `max|Δ| = 0.00e+00` + `golden_set.sha256` 101 条哈希 + 判据先写后动手，使每一轮探索都能落到同一个锚上。
3. **次序不可颠倒：底座先做，智能后上。**
   本仓库的时间线本身就是一次自然实验：2026-10-26 `GOAL.md` S0 确认 / `PROBLEM.md` M0 冻结 → M1–M5 机理引擎与验收（确定性资产） → R131–R160 判据、算子、证伪（把底座打磨到可验） → R163 服务接入 → R167 六视图平台 → R168 `operator_kit`（14 个 Agent 能力 + 21 个 MCP 工具）。**先有 86 批零回归的引擎，才有 Agent 的调度与发现**；反过来动底座的尝试（V2 注入、闭环同化）全部 NO_GO。

**分层模型（与仓库内 L0–L3 基线治理分层不同名，正文须显式区分）**

| 层 | 归属 | 内容 | 硬要求 |
|---|------|------|--------|
| 确定性底座 | 先研发、后冻结 | 数据 / 判据 / 算子 / 求解器（33 维 ODE、105 参数、58 底层算子、四环回退链） | 逐位可复现、默认不改写、hash 可验 |
| 确定性执行 | Agent | 跑批 / 扫描 / 比对 / 闸门 / 证据落盘 | 先写判据再动手，输出结构化证据 |
| 编排与探索 | Agent | 协作、计算、调度、发现（MCP 14 工具、`discover_residual`、`--jobs 8`、异步作业） | 只能作用于冻结底座，越界需授权 |
| 约束与授权 | 人类 | 目标、红线、验收口径、裁决、promote | 边界变更必须人裁决，L3 二次确认 |

**本章收口**：把这个命题写成可证伪形式——「若去掉冻结底座，Agent 的多轮探索会系统性产生不可判定的改进」，并说明本文后续 5 章就是这次判决性实验的记录。

## 2. 第 2 章 · 约束：人只做一件事，把不确定性写进文档

> 这一章是「可行性」的第一根支柱：**Agent 可行 = 约束可执行**。不是提示词写得好，是约束被写成了机器可验的文档。

**四类约束载体（逐类给文件与原文要点）**

| 类别 | 文件 | 约束了什么 |
|------|------|-----------|
| 目标约束 | `GOAL.md`（S0 目标确认单，2026-10-26 用户确认） | A/B/C 三档用途分级、±5% RMSE 验收基准、**§5 五条红线**（不接实产闭环 / 不放宽安全窗 / 不做在线 RL / 实产数据再训练需授权 / HAZOP 以文献为准）；R166 增补强调「§1/§3/§4/§5/§6/§7 一字未改」 |
| 受理冻结 | `PROBLEM.md`（M0 冻结）、`glossary.yaml` | 验收标准 v1.0 冻结、计量口径与时间戳纪律、数据可达性与 6 条 T7 假设登记 |
| 研发规范 | 外部 Workflow `flow-mvowqpw2`（§S0 / §S1 / §3.4 两阶段 / §3.5 组合栈 / §15 里程碑 / §11.4）、`docs/01_设计讨论…md`、`docs/deepening_plan.md`（PH1–PH5）、`docs/roadmap_next.md`（T0/T1/T2/T3 四波执行） | 流程先于代码；`docs/01…md:131`「每轮先写判据再动手，结果结构化落 `runs/ledger.jsonl`，ROUTE 四选一 PASS/REWORK/CAP/ESCALATE」 |

**六个硬闸门（人类介入点，稀疏但不可绕过）**

## 3. 第 3 章 · 迭代：Agent 原生研发的运行循环

> 可行性的第二根支柱：**多轮迭代不是「反复让 AI 改代码」，而是有收口件的闭环**。

**一轮的原子结构**
先写判据（轮次计划 `docs/r132_round_plan.md` / `r134_round_plan.md`）→ 一次性探针 `tools/rNNN_*.py`（493 个，按轮次编号，只读 / opt-in / 零引擎改动）→ 结构化证据 `runs/*.json` → ROUTE 四选一 → 轮次报告 `docs/rNNN_round_report.md`（36 份）+ 债务台账 `docs/rNNN_debt_ledger.md`（23 份）+ 契约升版 → 全量回溯（v3/v4/v5，自称「只读回溯、不擅自推进」）。

**三层账本**：`knowledge/ledger.jsonl`（111 行，含 `source: agent` 的 typed 记录）/ `runs/ledger.jsonl`（136 行）/ `ENGINE_CONTRACT.md` v1.97。负结果是一等产出（`paper/supplementary_methods.md:20`「A rejected or withdrawn claim is a valid record with its own evidence」）。

**迭代不劣化的四道常驻闸门**
① 零回归 86 批 `max|Δ| = 0.00e+00`、RMSE 2.3448%、86/86；② `r157_golden_hash.py --check`（101 条 sha256，修改/删除/改名单 ⇒ exit 1）；③ `acceptance.py --reuse`（HARD 4 / SOFT 6 / DET 2，全量 907.9 s）；④ pytest **33 passed in 509.47 s**、R166 终检 54/54、R167 平台闸门 25/25。所有候选默认 opt-in 关闭，`/api/simulate` 函数体逐字未改。

## 4. 第 4 章 · 成果一：Agent 研发出的算子库与求解器（确定性资产）

> 每项成果标注「研发轮次 / 判据来源 / 验收方式」，体现它们是 Agent 在约束下跑出来的，不是人工预先设计的。

**求解器（A 档）**
- `model.py` 33 维 ODE（逐项对照 MATLAB `indpensim_ode.m`）、`params.py` 105 参数、26 维 inp1、0.2 h 采样区间 BDF（`rtol=1e-3 / atol=1e-6 / max_step=0.01h`）、开环回放 + 前向 MV 时序修复。
- 验收：**RMSE 2.3448% / 86/86 ±5% / 零回归 `max|Δ|=0`**（`runs/r166_zero_regression.json`）；健康分级 77/5/4；形状指标 P relRMSE 中位 15.6%、峰比 1.060。
- 必须同句写明：**每批用各自标定参数 ⇒ 这是重建一致性，不是前瞻预测**；论文 E2 留批次迁移 RMSE 97.47%、约为重建误差 **41.6 倍**。

**算子库**
- `operator_kit`：**58 个底层算子 + 14 个 A/B/C/D 高层能力 + 4 个 v2 扩展**，不变量「不复制实现 / 不改旧目录一行 / 失败显式 / L3 五键保持拒绝」，验证 29/29 PASS。
- 专用算子族：四环回退链 `enkf_health` / `degradation_guard` / `mhe_step` / `steady_state_baseline` / `resolve_tier`（R161 落地、R163 接入现役 MCP 路径、默认关闭逐位不变）；轨迹级 `trajectory_metrics.py`；守恒 `conservation_metrics.py`；健康 `classify_health` / `shape_metrics`；故障注入 7 模式；寻优 `optimize.py`（5 MV / Nelder-Mead / `max_yield` 与 `track_target`）。
- B 档观测算子：观测器 v2 双通道，X 中位 **nRMSE 3.17%**、86/86 <15%；X 24.58%→2.28%、粘度 19.69%→5.57% 可交付；P/PAA 与菌丝区 A0/A1/A3/A4（`H_assim` rank=0 / nullity=4）结构不可辨识 ⇒ `GOAL.md` §2 第 7 行改标「不作交付宣称」。

**本章落点**：这些算子的共同属性是**确定**——固定输入输出、逐位可复现、默认 opt-in 不改写基线、每个都有 `runs/*.json` 证据。这正是第 1 章所说「先研发的确定性底座」。

## 6. 第 6 章 · 回证与可移植范式

- **用成果回证第 1 章**：正因为底座先冻结，Agent 才能在 167 轮里做协作/调度/发现而不失控；每一次试图绕过底座（V2 注入、闭环同化、改守卫）都被同一套闸门检出并归档。
- **提炼「Agent 原生研发」的可移植清单**（读者可直接抄的 7 条）：① 目标与红线写成机器可验文档；② 先研发并冻结确定性算子/求解器；③ 每轮先写判据再动手；④ 负结果与撤回编号归档、不删除；⑤ 判据自身必须做证伪测试（零信息对照 + 双向判据）；⑥ 评估权与授权权分离，L3 由人发起；⑦ 一切结论三处一致（契约 / state / `runs/*.json`）。
- **未闭合项**：L3 切换未执行、V1+ 含菌丝形态的数据资产、留出批次前瞻评估（D-89：28 批验证集从未留出）、第二个过程案例 E10、气体通道与液相碳账 ~30× 单位失谐待原文核证。
- **收尾**：这套系统最有价值的产出不是 2.3448%，而是 D-2…D-92 那 92 条债务编号、32 条纪律，以及「底座先冻结」这条次序。
