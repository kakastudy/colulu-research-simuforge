# 创新性分析 — 仿真算子库研究成果（2026-10-27）

> 定位：在项目语境内的创新盘点（对标起点 = S0 冻结的原始计划与业界常规做法），
> 全部条目均有可复核证据（runs/ 数据件）。诚实声明：机理模型本身是忠实移植（非新科学），
> 创新集中在方法论集成、评估认识论与工程架构三层。

## 一、方法论创新（算法层）

### 1. 时变维持系数调度（m_s_schedule）★ 核心方法创新
- **业界常规**：维持系数 m_s 为常数参数（MATLAB 模型亦如此），或引入完整死亡动力学模型。
- **本文做法**：把"校准参数"升维成"时间索引的调度算子" `[(t_switch, m_s_late)]`，用早期高 m_s
  （抑制 CO2d 增长、防 CO2 抑制级联）与晚期低 m_s（放开底物、匹配 V3 产率）**解耦
  "防崩溃"与"产率匹配"这对原本互斥的目标**。这是对缺失细胞死亡动力学的
  最小侵入式补偿：不改 ODE 结构、不改物理语义、不改 MATLAB 对齐性。
- **效果**：批 27 +14.0%→-0.2%、批 92 +11.9%→-0.6%、批 22 +10.8%→-0.0%（runstore 记录与 runs/*scan.json 佐证）。
- 定位：结构辨识 + 补偿控制的组合，可移植到任何"参数耦合矛盾"的机理校准场景。

### 2. 崩溃证据化三级判据（classify_crash）★ 评估认识论创新
- **业界常规**：阈值二值判据（穿越 X_crit_CO2 = 崩溃）。
- **本文做法**：以病理证据链（pH 窗、P 完整性、产率损失）三级分级 normal/benign/catastrophic，
  时间分数仅记录不作硬闸；**判据变更本身由 V3 数据反例取证背书**（批 23：
  穿越且产量 -0.4% 无损、V3 同批 S 耗尽型生长停滞、晚期 m_s 上调 12 组不可阻止穿越）。
- **效果**：灾难性崩溃 1/12 → 0/12；避免了"为通过判据而扭曲参数"的反模式
  （晚期 m_s 强改反而引发 pH 钳位 3.00 病理）。
- 定位：评估模型的数据取证式重构——先证明旧判据制造假错误，再以证据链替代。

### 3. B 档两阶段可辨识性救援（在线网格 + P_offline 锚定）★ 估计策略创新
- **业界常规**：直接上 UKF/EnKF/MHE 状态估计（M2 冻结路线）。
- **本文做法**：受算力证据约束（33 维刚性 ODE×8s/评估 → sigma 点不可承受），改走
  **两阶段降维**：第一阶段在线通道网格估"生长端参数"（μx/m_s/ΔTcin）；
  第二阶段把 μp 锚定到工厂真实拥有的离线化验 P（12h 粒度/滞后 4h）。
  产率偏差独立评估不参训（防目标泄漏）。
- **效果**：5/5 μp 崩塌批救回（-92%~-96% → +0.17% ~ +12.5%）；确立设计点结论
  （P_offline 单目标 > 联合 2D 目标——在线权重反而干扰 μp 辨识）；刻画 μp 极端敏感度
  （每 0.001 步距 ≈ 60% 产量摆动，批 92 达满 ±5% 命中）。
- 定位：在"全量 UKF 不可行"约束下的可辨识性工程解，为 UKF 彻底欠账提供了过渡层。

### 4. C 档 MV 倍率参数化 + 有效域证据化（反设计）★ 优化问题重构创新
- **业界常规**：自由优化完整补料曲线（高维、易撞崩溃域、结果难解释）。
- **本文做法**：决策变量重构为**参考配方的倍率乘子**（Fs/Foil/Fpaa/Fg/RPM，2–5 维，
  物理可解释、工厂可执行）；以"无灾难崩溃"为硬约束 + 发散守卫；发现并登记
  **Fs 倍率双稳态分岔**（批 8：Fs×0.97+ 灾难断裂 / ≤0.95 正常）为引擎有效域；
  双目标框架：track_target（反设计对准目标产量）与 max_yield（生产设计）。
- **效果**：批 22 正中 V3 目标（-0.0%）、批 60 收敛 -0.09%、批 36 -3.4%；
  12/12 批 ±5% 达标；单批评估成本仅 28–34 次仿真（213–294 s）。

## 二、数据科学创新（数据层）

### 5. 基准数据集内在缺陷的定量取证（V3 尾气通道 30× 不自洽）
- **做法**：批级 C/N 元素平衡核算（引擎化学常数 + 化验口径）→ 发现 V3 尾气 CO2 通道
  对应碳量（~0.15 t C/批）比液相账需求（~5.5 t C/批呼吸）低约 30 倍，且 12 批误差一致
  （-60%~-67%）、机理引擎侧复核呼吸归认份额 +56%~+66% 批间稳定 → **排除噪声解释**。
- **意义**：(a) 防止把数据层缺陷误判为求解器失败（若直接用原文标准，§4.3 会被误判 FAIL）；
  (b) 为验收口径的证据化改判（RQ 闭合 + N 平衡 + C 呼吸归认账）提供定量依据；
  (c) 登记"单位溯源待数据方原文"的诚实缺口，而非静默自洽。

### 6. V3 原始数据的再挖潜（检索不可用环境下的替代方案）
- 环境无外网（web_search/web_fetch 均不可用），"检索下载其他资源"改道：
  从本地 2.5 GB 原始 CSV 重解析出新证据（V3 无 CO2d 传感器列——2239 列核查；
  批 23 X_offline 衰减轨迹；PAT_ref 拆列缺陷）作为崩溃改判与评估口径的直接证据源。

## 三、工程架构创新（服务层）

### 7. MCP 协议 Agent 服务层（9 工具，双传输）
- 把三档算子封装为 Agent 可调用工具（求解器能力清单/仿真/评估/黄金集复验/
  软测量两阶段/反设计/轨迹验收/元素平衡），校准单一事实源（calibration.py）自动注入
  （Agent 无需知道内部口径）；**崩溃分级以"证据链数组"为一等输出**——I2 失败可见
  原则贯穿到 Agent 契约层。stdio + HTTP 双传输均 E2E 验证。

### 8. 记录持久化引擎（runstore）与"计算历史即数据"
- 参数哈希 run_key（canonical JSON→SHA-1）；轨迹 pickle + 元数据 JSON 双文件；
  B/C 档把**计算过程本身**（54 组合 sweep、μp 扫描、寻优收敛历史）持久化，
  趋势图可在历史记录上复现——"重放快照"与"重放过程"都秒开。
- 单批评估成本高（8 s）的现实约束下，该设计把交互成本从 O(8s×N) 降为 O(0)。

### 9. 双账本证据工程 + 全链路可复核性
- runs/ledger.jsonl（证据账簿，逐结果登记假设/数据窗/结论/路由决策）+
  knowledge/ledger.jsonl（知识账簿，T 级来源分层）；每个数字都能在
  "原始依据 → 工件 → 文档叙事"三级链路上复核。这是把 SCI 可重复性要求
  落到工程库的做法（本文报告本身的全部图表即由这些工件程序化生成）。

## 四、诚实定位（非创新的部分）

- 机理模型/守卫/回放结构：忠实移植（价值在保真与可验证，不在原创）；
- m_s 时变调度：面对物理缺失（细胞死亡）的代理补偿，非新机理；
- 状态估计器（UKF 全量）、置信区间覆盖率（I3）、故障注入算子：未实现（拍板登记 D1/D2/D4）；
- 基准数据集自身的可复现性缺陷（统计 CSV 与 V3 非同运行）属于数据集问题，本文仅取证登记。

## 五、一句话总结

**以"数据取证的评估改判 + 时变参数调度 + 两阶段降维估计 + 配方倍率反设计"
四个方法论组件，绕过了"全量 UKF 不可行 / 崩溃阈值误判 / m_s-产率互斥 / 高维寻优不稳健"
四个原路线障碍，并把三档算子+全过程证据打包成 Agent 可调的 MCP 服务。**
