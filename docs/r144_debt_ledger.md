## 一、本轮关闭

### D-30　b92 尾段数值奇异 → 产量积分器依赖 —— **关闭（机制已定位）**

| 项 | 记录 |
|---|---|
| 原表述（R143） | "b92 在 t≈217.6 起 pH 崩到 3.000，Radau 直接失败，产量依赖积分器配置" |
| **第一层** | `pH = 3.000` **不是模型预测**，是 `simulate.guards()` 把 `y[6] <= 0` 钳成 `0.001`（`-log10(0.001) = 3.000`）。守卫覆盖 states 0–30，`y[6]` 就是 `[H+]` |
| 实测追踪 | t=217.2 `[H+] = 3.6112e-08`（pH 7.442）→ t=217.4 `[H+] = **−1.2843e-05**` → 钳位 `[6]` → pH 3.000。**一步 0.2 h 内跨过零点** |
| **第二层** | `model.rhs` 的 basic 分支（pH ≥ 7）含 `−y7_use`，其中 `y7_use = Kw/[H+] − [H+]` ⇒ `d[H+]/dt ⊃ −Kw/[H+]`，**正反馈**。解析积分给出**有限时间爆破** `t* = [H+]²/(2Kw)`：pH 7.0 → **0.500 h**、pH 7.44 → **0.065 h（3.9 min）**、pH 8.0 → 0.005 h |
| 与网格的关系 | 采样步长 **0.2 h** 与 pH 7.0 的爆破时间 **0.5 h** 同量级 ⇒ **只要 pH 越过 7，0.2 h 网格上崩落是必然的**。这也解释了 Radau 为何在 217.4 拒绝积分（撞上 `[H+]→0` 奇点） |
| **第三层** | 为什么 pH 会越 7：模型尾段 pH 从 t=205 的 **6.287** 抬到 217.4 h 的 **7.442**（中间仅 ±0.03 抖动，非严格单调；末步 +0.287），而**碱流并不大**（t≥200 的 Fb 中位 **20.3 L/h**、`Fb≥224.99` 占比 **0%**）⇒ 不是灌碱过多，是模型**产酸项（`ph_prod`/`r_p`）在 P 衰减期过小** |
| 域外证据 | 全库 100 批实测 pH **5.396–6.766**；`pH>7` 的批 **0/100**、`pH>6.8` 的批 **0/100** ⇒ **basic 分支在真实系统里是死代码** |
| 尺度错配 | 守卫对 31 个状态共用 `0.001` 下限。对 `A3/A4`（死菌）、`n0…n9`（链长分布）、`Q` 无害；对 `[H+]`（物理范围 1e-8~1e-6）等于强制 pH 3 —— 是 pH 6.5 平衡值的 **3162 倍** |
| 非移植 bug | `indpensim.m` 守卫同为 `for n=1:1:31 ... = 0.001`；`indpensim_ode.m` basic 分支同为 `y(7)=(1e-14/y(7)-y(7))` 后接 `(-B-sqrt(B^2+4e-14))/2-y(7)`。**Python 侧逐行忠实，缺陷是参考实现自带的** |
| 影响面 | 86 批合规集内 **5 批**撞上：**b37（172.8 h）、b50（203.0 h）、b51（212.2 h）、b91（232.2 h）、b92（217.4 h）** |
| 混沌检验 | 输入 ×`(1+1e-6)`：**b37 极差 70.96 pt**（−2.29%→+68.67%）、**b50 60.00 pt**（−0.26%→+59.72%）、**b92 4.10 pt**（+1.22%→+5.32%）、b91 0.36 pt、**b51 0.00 pt**、**b8（对照）0.00 pt** |
| 结论 | D-30 的实质**不是"积分器选错"**，而是「模型尾段 pH 偏 0.7 → 撞进域外的病态分支 → 统一守卫把数值问题固化成 pH 3」三件事叠加。三件缺一，都不会出现"pH 崩到 3 且产量仍达标" |
| 处置 | ① 模型验证域定为 **pH ∈ [5.0, 6.8]**，越界记 `domain_violation`；② 五批产量退出 ±5% 合规计数、改报区间；③ 守卫按状态给下限（opt-in，默认不变）列入待办（D-33） |

## 二、新增

### D-32　尾段产酸项偏小，导致 pH 越出验证域　**🔴 L2 阻断项（新）**

| 项 | 记录 |
|---|---|
| 现象 | b92/b91 尾段模型 pH 持续上抬并越过 7（从 t=205 的 6.287 升到 217.4 h 的 7.442）（实测数据上限 6.766，从不越 6.8） |
| 已排除 | 碱流过大（t≥200 的 Fb 中位 20.3 L/h、最大 80、贴上限占比 0%） |
| 定位 | 产酸项 `ph_prod = r_b0 + r_e1 + r_d4 + r_d1 + m_ph*total_X` 与 `r_p`，在 P 进入衰减期后过小 |
| 性质 | **建模问题，非数值问题**。与 D-20（CER 17% 固定偏置）、D-26（观测模型缺非活性组分）同族 |
| 为什么不本轮修 | 改产酸项=改化学计量=重标定全库，须单独评审；本轮只确认"越界不是数据里的酸碱事件" |

### D-33　守卫下限应按状态区分（`[H+]` 不能用 0.001）

| 项 | 记录 |
|---|---|
| 问题 | 31 个状态共用 `0.001`，对 `[H+]` 等于强制 pH 3 |
| 建议 | 加 opt-in 参数（如 `ph_floor=1e-9` ⇒ pH 上限 9），**默认 0 保持逐位不变**；实现方式与 `death_mode` 一致：新参数默认关闭 |
| 前置 | 必须先在 D-32 上把 pH 拉回域内，否则只是把 pH 3 换成 pH 9，问题依旧 |

### D-34　"守卫钳位"未纳入批量验收必检项

| 项 | 记录 |
|---|---|
| 问题 | `guards()` 不报错、不告警，静默改写状态。5 批被改写，此前**无一份报告提到过** |
| 建议 | 批量验收输出中固定附「钳位统计（按状态索引）」，任何 `[H+]` 钳位即置 `domain_violation` 标记 |
| 工具 | `tools/r144_d30_sweep.py` 已可直接产出该统计 |
