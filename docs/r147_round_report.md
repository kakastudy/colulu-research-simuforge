# R147 回合报告 —— D-36：钳位不是数值 bug，是当前标定的支撑结构

> **【R148 勘误 · 2026-11-04】**：本报告中"守卫把 pH 写成 3 并**维持** N 个样点"的表述**不准确**。

> 另：本文的"钳位样点 N"实为"pH≈3 的样点数"，非"守卫改写次数"。详见 `docs/r148_round_report.md` §3。

## 1. 摘要

R145/R146 一直把 D-36 描述成"守卫钳位改写动力学（`mu_h ×8.43`）"，隐含假设是：**把钳位去掉，问题就解决了**。

本轮把"水解项在 pH 方程里怎么算"提升成显式三态口径（`net` / `prod_only` / `all_acid`），在 **15 批**上做对比（5 个钳位批 ∪ 12 批黄金集，b91/b92 重复计入）。结论有两个，都与原假设相反：

1. **钳位不是外挂的数值保护，是产量的必要组成。** b37 当前 −2.29% 的偏差，是靠 pH 崩到 3、`mu_h` 放大 8.43 倍、多水解掉 **69%** 产物凑出来的（P 末/峰：0.309 vs 0.748）。去掉钳位后 b37 变 **+61.78%**。
2. **三个口径全部破线**（12/12 → 5/12 → 3/12），说明 `r_p` 的口径**不是可调的旋钮**，D-36 不能靠改这一项修掉。

由此 D-36 的性质要改：它不是"数值实现缺陷"，是**标定前提缺陷**——现有 `μp / k_deg / γ1 / m_ph` 是在"pH 严重偏酸 + 过度水解"的工况下标定出来的，与真实工况不自洽。

## 2. 为什么中间那一档必须补上

R145 只试了两个端点：

| 口径 | pH 方程里水解项的符号 | 物理说法 |
|---|---|---|
| `net`（默认，MATLAB 原文） | `−mu_h·P` 经 `+γ1` ⇒ **产碱** | 水解碱化 |
| `all_acid`（`ph_hyd_acid=True`） | `+mu_h·P` 经 `+γ1` ⇒ **产酸** | 青霉噻唑酸是一元羧酸 |

两端都不对，但中间那一档从未验证：

**`prod_only`**：水解在质子平衡里**完全不计**
```
r_p_ph = r_p + mu_h·P = mu_p·ρ·v·P_inhib·DO2·PAA      （只剩产素项）
```

物理依据：β-内酰胺开环确实多一个可解离 COOH（pKa≈2.7），但同时**消耗一分子水**，净质子变化接近零。把它写成"碱化"（默认）或"产酸"（R145）都是给一个近似零的量强加符号。

实现上三者统一成 `r_p_ph = r_p + _adj · mu_h · y[3]`，`_adj = 0 / 1 / 2`。

## 4. 核心发现：钳位是产量的必要组成

五种被钳位批（b37/50/51/91/92）在 `net` 下偏差是 −2.29 / −0.26 / −0.03 / +3.52 / +1.36（**全在 ±5% 内**）；
在 `prod_only` 下变成 +61.78 / +39.25 / +13.88 / +19.73 / +12.91（**全部破线，且全为正**）。

全部同向偏正，含义明确：**钳位期间多出来的水解，正好抵消了产量标定本身的偏高**。

单批看 b37 最清楚：

| b37 | pH max | 钳位样点 | pH 末 | P 末/峰 | 产率 |
|---|---|---|---|---|---|
| net | 9.185 | 186 | 3.004 | **0.309** | −2.29% |
| prod_only | 6.701 | 0 | 6.107 | **0.748** | +61.78% |

`P 末/峰 = 0.309` 意味着**峰值产物只剩 30.9%**，其余 69.1% 被水解掉。真实青霉素发酵的尾段产物损失远不到这个量级（R138 测的 k_deg 半衰期 114 h，37 h 窗口只该损失约 25%）。

也就是说：**b37 现在的"精确"是一个数值事故的净效果**，不是在正确的动力学下标定出来的。

## 5. 三个口径全破，说明口径不是旋钮

`net` 12/12 → `prod_only` 5/12 → `all_acid` 3/12。

如果 D-36 是"符号写错了"，那么至少有一个改成对的方向应该**同时**改善悬崖和精度。实际是：**两个改法都在消除悬崖的同时毁掉精度**。

这排除了"D-36 可以靠改 `r_p` 口径单独修掉"这一整类方案（R145 已经排除 `all_acid`，本轮排除 `prod_only`）。

顺带得到：**`net` 的 12/12 不是"模型对了"，而是"两个错误互相抵消"**。

## 6. b91/b92 的第二个产碱源

`prod_only` 已经去掉水解产碱，但 b91 仍越 7.200 / 钳位 29 样点，b92 越 7.491 / 钳位 11。

说明 pH 上升**不止一个来源**。`acid = γ1·(ph_prod + r_p_ph)` 在 `prod_only` 下恒非负（`ph_prod > 0`，`r_p_ph = 产素项 ≥ 0`），所以 acidic 分支的产酸项不会再变号。

剩下的候选只有 buffer 项 `(root − y7_use)`：`B` 里含 `abc·(Fa − Fb)·step1`，**碱进料 `Fb` 大时 `B` 变正、`root` 可小于 `y7` ⇒ `dy[6] < 0` ⇒ pH 上升**。

这指向 **缓冲容量**（`m_ph / γ1` 的配比），而不是产酸源。这一条留作 D-39 登记，不在本轮展开。

## 7. 死锁的完整形式（比 R146 更严）

R146 的形式是「修 pH 需要抬 pH，而抬 pH 正好推向悬崖」。本轮补上了另一半：

```
            ┌─ 想抬 pH 让模型对齐实测（模型系统性偏酸 0.1–0.57）
            │
   γ1 / m_ph 调大 ──→ pH 上升 ──→ 越 7 ──→ basic 分支爆破 ──→ 钳位到 3
            │                                              │
            │                                              ↓
            └──────────────────────────────  mu_h ×8.43 ──→ 多水解 69% ──→ 产量"恰好"对上
```

**钳位既是障碍（不让你抬 pH），又是支撑（撑着当前产量精度）。** 两者是同一个结构的两面。

所以 D-36 与 D-35 **不可分解**：单独修钳位 ⇒ 5 批破线；单独重标定产量 ⇒ 在污染工况上标定，无效。

### 8.1 一处自己造成的错，记录在案

首版 `ph_rp_mode` 只透传到 `integrate_interval` 内部的 `f()`，**漏了 477 行 `integrate_interval(...)` 这个调用点**。结果三口径跑出**完全相同**的数字（b37 三个都是 −2.29%）。

这不是"引擎没生效"，是"参数根本没到"。教训与 R145 的 `ph_hyd_acid` 未定义同源：**新增一个贯穿三层的参数（`simulate_open_loop` → `integrate_interval` → `rhs`），必须逐层验证"它真的到了最内层"**，光看 grep 命中数会漏掉调用点。

判据：`grep -c "ph_rp_mode"` 命中 6 处看似齐全，实际 477 行那处被漏。正确做法是**跑一条已知会改变结果的臂，看它是否真的改变**——本轮三条臂结果全同，这个"全同"本身就是报警信号。

## 9. 处置

### 9.1 D-36 重新表述

| 项 | 原表述（R145/R146） | 新表述（R147） |
|---|---|---|
| 性质 | 数值实现缺陷（守卫写错动力学） | **标定前提缺陷**（参数在污染工况下标定） |
| 可单独修 | 是 | **否** |
| 修掉后的后果 | 精度提升 | **5 批破线**（最多 +64 pt） |
| 依赖 | 阻塞 D-35b | 与 D-35b **互为前提** |

### 9.2 引擎

`ph_rp_mode` 三态口径已进引擎，**默认 `"net"`，86 批逐位不变**。它作为**诊断入口**存在，不是修复路径——三条路都已被证伪，没有一条可以设成默认。

### 9.3 下一步的唯一可行路径：联合求解

不再尝试"先修哪个"，改为在**一个目标函数**下同时动 `γ1 / m_ph / μp / k_deg`：

1. 目标 = pH 轨迹残差 + 产量残差，**约束 = pH 不越 7**（硬约束，不是惩罚项）
2. 初值取当前 86 批标定值
3. 用可行域投影（不越 7）而不是线搜索——R146 已证线搜索在悬崖边必然失效

这条路的前提是**先把 pH 越界变成一个可判定的硬约束**（即 D-34 的"越界计数入验收必检"），而不是靠钳位把越界藏起来。

## 10. 方法论

**第 14 条 —— 当"修掉缺陷"会让指标变差时，先怀疑指标是缺陷养出来的。**

b37 的 −2.29% 看起来是"模型准"，实际是钳位多水解 69% 的结果。判据很简单：**把缺陷去掉，如果精度大幅变化（同向、成规模），那精度就不是模型的属性，是缺陷的属性**。

本轮 5 批全部同向偏正（+11.55 … +64.07 pt），这个"同向"是判决性的——随机误差不会同向。

**第 15 条 —— 排除一个旋钮要比确认一个旋钮便宜。**

三口径各跑 15 批（5 分钟），就把"改 `r_p` 口径"这一类方案整体排除。相比之下 R146 的线搜索花了 40 分钟才排除一个方向。**在动手调参之前，先把"这一类方案是否可能存在"用最粗的网格打掉。**
