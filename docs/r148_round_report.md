## 1. 摘要

R147 台账 §三 定了五步路径，其中第 1 步是"把 pH 越界做成硬约束（不是惩罚项）"，并写明
**"没有它，第 3 步的任何搜索结果都不可信"**。本轮做第 1 步和第 2 步（在 `invalid` 判据下重算 86 批）。

三件事，第二件是意外：

1. **`validity()` 落地**：与 `classify_crash` 并列的独立判定，判据是「`pH_H` 从未被守卫改写」且
   「守卫**前**的 pH 从未达到 7.0」。不改 `classify_crash`，历史验收数字不受影响。
2. **推翻前三轮的机制叙述**。R145/R146/R147 反复写"守卫把 pH 写成 3 并**维持** 186 / 129 / 288 个样点"。
   实测（`guards` 旁路审计 + 逐步 spy）：守卫对 `pH_H` **只改写 1 次**。之后那 186 个 pH≈3 的样点，
   是 ODE 自己给出的，守卫一次都没再碰。
3. **越 7 是不可逆悬崖**：b37 从 7.0004 到 9.1852 只用 **0.6 h**（3 个采样步），到崩落再一步。
   0.2 h 的采样步长在结构上追不上，所以"轻微越界"不存在——任何越 7 都等价于崩塌。

第 2 件直接影响处置方向：**改守卫无效**（它只出手 1 次）。这也解释了 R147 为什么把 `r_p` 口径
三态全试一遍都没用——改符号不改速率结构。

## 2. 引擎改动

四处，全部为**旁路观测或新增 API**，不参与数值路径。

### 2.1 `guards(y, audit=None)`

```python
def guards(y, audit=None):
    ...
    for i in range(31):
        if y[i] <= 0:
            if audit is not None:
                audit.append((i, float(y[i])))   # ← 新增，仅记录
            y[i] = 0.001
    if y[IDX["DO2"]] < 2:
        if audit is not None:
            audit.append(("do2", float(y[IDX["DO2"]])))
        y[IDX["DO2"]] = 1.0
```

不传 `audit` 时与原实现逐位相同。用途：把"pH 被钳到 3"从**靠 pH 阈值猜**（`pH ≤ 3.05`）
变成**按状态索引直接数**。

### 2.2 `sim["pH_pre"]` 诊断列

主循环里在 `y = guards(y)` **之前**取 `y[IDX["pH_H"]]` 并换算成 pH；若 `y6 ≤ 0` 记 `NaN`
（不伪造一个 pH）。这一列回答的是"模型本来想说什么"，而 `sim["pH"]` 是守卫改写后的值。

### 2.3 `sim.attrs["guard_audit"]`

```python
{
  "n_steps": 1049,                 # 采样步数
  "tally": {"pH_H": 1, "Q": 5},    # 按状态的改写次数（累计）
  "tally_first": {...},            # 第 1 步单独记（见 §6.3）
  "ph_nonpos_steps": 1,            # y6 ≤ 0 的步数
  "ph_max_pre": 9.185,             # 守卫前的 pH 最大值
  "n_ph_over7_pre": 5,             # 守卫前 pH ≥ 7.0 的步数
  "audit_consistent": True,        # 自检恒等式（见 §6.1）
}
```

### 2.4 `validity(sim, ph_crit=7.0)`

判据两条，缺一即 `invalid`：

| # | 条件 | 理由 |
|---|---|---|
| 1 | `pH_H` 从未被守卫改写 | `y[6] ≤ 0` ⇒ `[H+]` 为负，物理不可能；纯度是数值崩溃 |
| 2 | 守卫**前**的 pH 从未 ≥ 7.0 | 越 7 进入 basic 分支（含 `−Kw/[H+]` 正反馈），0.2 h 内必爆（§4） |

**其他状态的钳位不作为 `invalid` 判据**。底物耗尽时 `S → 0` 被钳到 0.001 是常规数值保护，
几乎每批都有；把它们算进 `invalid` 会让判定失去鉴别力（§6.3 实测 88/88 批全中）。
这些只在 `other_clamped` 里报出，供人工审查。

## 3. 机制修正：不是"守卫维持"，是"速率塌缩的伪平衡"

### 3.1 实测

对 b37 用 `guards` 旁路审计 + 逐步 spy：

```
guards 被调用 1049 次；y6 ≤ 0 的调用 1 次：
  step=864  y6_pre=-9.339e-06 -> 1.000e-03  (pH 3.0000)
```

**只有 1 次**。可是 `sim["pH"] ≤ 3.05` 有 **186** 个样点。这 186 个点是怎么来的？

### 3.2 逐步看

| idx | t (h) | `pH`（守卫后） | `pH_pre`（守卫前） | 由此反推 `y6` |
|---|---|---|---|---|
| 860 | 172.4 | 7.07447 | 7.07447 | 8.424e-08 |
| 861 | 172.6 | 7.21286 | 7.21286 | 6.125e-08 |
| 862 | 172.8 | **9.18517** | 9.18517 | 6.529e-10 |
| 863 | 173.0 | 3.00000 | **NaN** | ≤ 0（守卫写入 1e-3） |
| 864 | 173.2 | 3.00003 | 3.00003 | 9.999e-04 |
| 865 | 173.4 | 3.00007 | 3.00007 | 9.998e-04 |
| … | | | | |
| 1048 | 210.0 | 3.00390 | 3.00390 | 9.991e-04 |

从 173.2 起，`y6` 就停在 1e-3 附近，**守卫再没有改写它**（1e-3 > 0，条件不成立）。

### 3.3 速率

| 区间 | d(pH)/dt |
|---|---|
| 越界前（t < 172.8） | **+3.55e-01 pH/h** |
| pH≈3 段（173.0–210.0） | **+1.05e-04 pH/h** |

- 185/185 步**单调上升**（不是定态，只是极慢）
- 37 h 总涨幅 **0.0039**
- 外推回到 pH 7.0 需要 **6.8 万小时**

⇒ 系统进入一个**速率被压低约 3378 倍的伪平衡**。它不是守卫制造的，是 pH 方程本身在
`y6 ≈ 1e-3` 处近乎平衡（`acid + root ≈ y6`），只是斜率极小。

### 3.4 为什么这条修正重要

R145 的结论"`mu_h` 在钳位期被放大 8.43 倍 ⇒ 产物被多水解" **依然成立**——
pH 确实在 3，`k4(3.0)/k4(6.5) = 8.427`。成立的是结论，不是机制。

机制错了会误导处置：若以为是"守卫反复写"，自然推论就是"改守卫"。实际守卫只出手 1 次，
**改守卫什么都不会发生**。真正要动的是让 `dy[6]` 在 pH→3 时不要塌缩的那个结构
（D-39 指向的缓冲容量 `m_ph/γ1`）。

## 4. 越 7 是不可逆悬崖

b37 越界段，全精度：

| t (h) | 172.0 | 172.2 | 172.4 | 172.6 | 172.8 | 173.0 |
|---|---|---|---|---|---|---|
| pH | 6.9999 | 7.0004 | 7.0745 | 7.2129 | **9.1852** | 3.0000 |
| 状态 | — | 越 7 | basic 分支 | — | 爆破 | 守卫写入 |

从"刚好越过 7.0"到"大到不可用"用时 **0.6 h = 3 个采样步**。R128/R145 给过解析式
`t* = [H+]²/(2Kw)`：pH 7.0 时 `t* = 0.5 h`，pH 7.2 时 `0.198 h` —— 与实测吻合。

**推论**：不存在"轻微越界"。硬约束必须写成布尔判定，不能写成"允许越 0.2 以内"的软约束。
这是第 1 步采用 `pH_pre ≥ 7.0 ⇒ invalid`（而非代价函数）的直接依据。

两类性质不同：

- **`clamp`（5 批）**：pH 越 7 → 崩 → 守卫写入 → 锁死在 3（§3）。产量由钳位期多出来的水解决定。
- **`over7`（4 批）**：pH 越 7 但**自愈**回到 6.7–7.0，守卫从未出手，没有钳位样点。

`over7` 的存在说明：**越 7 不等于必崩**（是否爆破取决于该步 `[H+]` 有多小），但越 7 之后的
那段轨迹已经进入 basic 分支的定义域，返回值不再可信。所以判据必须包含"越 7"本身，
不能只判"是否被钳位"。

### 5.3 三个反直觉但重要的结论

**(a) invalid 批不表现为"误差大"。** 9 批**全部**在 ±5% 内，最大 4.12%。它们无法用误差筛掉，
只能靠有效性判定。也就是说：过去 `86/86` 的"全部通过"里，有 9 批是**通过了但不算数**。

**(b) 崩得最狠的批，误差反而最小。** 按类型分组：

| 组 | n | RMSE |
|---|---|---|
| `valid` | 77 | 2.303% |
| `clamp`（崩到 3） | 5 | **1.978%** |
| `over7`（越 7 自愈） | 4 | **3.346%** |

崩到 pH 3、被多水解 69% 的那些批，产量误差最小；只是短暂越 7 的批，误差反而最大。
这是 R147「钳位多水解系统性补偿了产量标定偏高」的**定量确认**——补偿是真的，
所以补偿得越彻底（崩得越深）的批，表面误差越小。

**(c) 可行域在 pH 方向上只剩 0.018。** valid 集合里 `pH_pre` 上界是 **b59 = 6.982**，
距阈值 7.0 只有 **0.018**；中位数 6.741。

这意味着当前解**已经顶在约束面上**。任何"抬 pH"的调整都立刻违规——R146 在 12 批上
看到的余量是 0.198（b22），在 77 批上缩到 0.018，薄了 11 倍。
**D-35b 的可行域在 pH 方向上的厚度就是 0.018 个 pH 单位。**

### 5.4 阈值 7.0 本身站得住，但"数据覆盖"是另一回事

必须先排除一个反驳："也许真实过程本来就会到 7 以上，7.0 这个约束是人为的"。

实测 pH 包络（86 批）：**全局上界 6.759，没有任何一批超过 7.0**。逐批看：

| 批 | 实测 pH 范围 | 模型 `pH_pre` max |
|---|---|---|
| 59 | [6.404, 6.708] | 6.982 |
| 95 | [6.427, 6.700] | 6.936 |
| 37 | [6.391, 6.676] | **9.185** |
| 91 | [6.451, 6.697] | 8.016 |

⇒ 越界是**纯模型行为**，不是数据要求。7.0 作为数值有效性阈值成立（相对实测上界留 0.24 余量）。

但由此暴露出**两个必须分开的约束**：

| 约束 | 阈值 | 性质 | 用途 |
|---|---|---|---|
| **数值有效性** | `pH_pre < 7.0` | 硬：越 7 进 basic 分支，0.2 h 内必爆（§4） | 判 `valid` / `invalid` |
| **数据覆盖** | `pH_pre ≤ 本批实测峰值` | 软：越界是外推，风险但不失效 | 报出，不判 invalid |

按软约束统计 valid 的 77 批：**62/77 批（80.5%）模型 pH 峰值超出本批实测峰值**，
中位超出 **0.116**，最大 **0.326**（b73：6.924 vs 6.598）。

### 5.5 一个更精确的诊断：不是"偏酸"，是"振幅过大"

R145 说"开环模型 pH 系统性偏酸 0.1–0.25"，R146 已用 12 批数据推翻（偏差 −0.007…−0.572，
差 80 倍，是抽样偏置）。本轮数据给出替代解释：

- **峰值**：62/77 批模型**高于**实测（中位 +0.116）
- **均值**：R146 实测多为**负**（模型偏低）

两者同时成立 ⇒ 模型 pH 的**动态范围比实测大**：峰更高、谷更低。
不是整体平移，是**振幅过冲**。

这直接指向产酸通道的增益：`γ1` 既放大产酸也放大产碱，增益偏大就会同时抬高峰值、
压低谷值。与 R146 的灵敏度结论一致（`d pH/d lnγ1` = −0.66…−1.56，γ1 主导；γ2 几乎无效）。

**注意**：这不是"调小 γ1 就行"。γ1 同时进入 `dy[6]` 的产酸项与缓冲项，且当前解已顶在
7.0 约束面上（§5.3c），缩小 γ1 会把 pH 峰值降下来、但同时改变缓冲容量——须与 `m_ph` 联合求解，
这正是第 3 步（台账 §三）的内容。

## 6. 我自己犯的三个错

记在这里不是因为值得表扬，是因为其中两个会**静默改变核心指标**，而它们都没有报错。

### 6.1 别名 bug：一次改写被记两遍

首版计数写成：

```python
_tgt = _guard_tally_first if _guard_n_steps == 1 else _guard_tally
for _hit in _audit:
    _guard_tally[_k] = _guard_tally.get(_k, 0) + 1
    _tgt[_k]        = _tgt.get(_k, 0) + 1      # ← 当 _tgt is _guard_tally 时，同一个键 +2
```

`step > 1` 时 `_tgt` 与 `_guard_tally` 是**同一个 dict**，两行落在同一个键上 ⇒ 计数翻倍。
b37 的 `n_ph_clamp` 因此从 1 变成 2，`valid` 布尔值不受影响（`>0` 仍成立），
**所以只看 `valid` 名单是查不出来的**。

抓到它靠一条恒等式：

```
guards 的改写条件 (y[6] ≤ 0)  ≡  ph_nonpos_steps 的判定条件
⇒ tally["pH_H"] 必须等于 ph_nonpos_steps
```

实测 `tally=2, nonpos=1` ⇒ 违反。这条恒等式已写成 `guard_audit["audit_consistent"]` 常驻自检。

### 6.2 批集：`sorted(COMBINED)` 是 88 批，不是 86

首发跑出 `n=88`。`COMBINED` 有 88 个键，而 `runs/final_validation_v2.json` 的验收集是 86 批
（多出 **b99、b100**）。若不管它，"x/86" 与 "x/88" 两个分母会混在同一份报告里——
与 R146 的 `dist_flag` 事故同型（都是"用了不是 SSOT 的那个入口"）。
已改为从验收集读批号，并断言每个批号都在 `COMBINED` 中。

### 6.3 suspect 判据过宽：首步钳位不是崩溃信号

首版把"任何非 pH 关键量被钳位"都记为 `suspect`，结果 **88/88 批全部命中**。
查 `other_clamped` 分布：`A3, A4, n0…n9, nm, phi0` **每批恰好各 1 次** —— 这是零初值在第一步
被守卫写成 0.001，属初始化现象。

修正：`tally_first` 单独记第 1 步，`other_clamped` 报的是**扣除首步之后**的剩余。
修正后 `suspect` 只剩 `Q`（热平衡，非浓度）与少数 `P`。

**教训**：一个判据如果对全部样本都成立，它就不是判据，是常数。

   不得进入任何"x/y 达标"的分子或分母。
2. **`over7` 是独立类别**。此前只用"是否被钳位"筛，4 批 `over7` 全部漏网（§5.2）。
3. **数据覆盖是软指标**。`pH_pre > 本批实测峰值` 报出但不判 `invalid`（§5.4），
   因为越界不等于失效；但它意味着该段轨迹在数据之外，引用时须注明外推。

**作废**：R147 的「`n_clamp>0` 即 `[clamp-tainted]`」判据不完整——它只覆盖 `clamp`，
漏掉 `over7`。R145 的「62 批稳健 / 19 依赖 / 5 由钳位窗长决定」继续作废。
