### 2.1 T1-1：`acceptance.py --reuse` 的 health 恒真 ★已修

**根因**：`runs/r151_shape_baseline.json`（D-38 之前生成）86 行**无 `health` 字段**（只有旧的 `crash` 字段），
而 `shp.summarise()` 对缺失字段**静默返回 0 计数** ⇒ `catastrophic_batches=[]` / `degraded_batches=[]`
⇒ **G2（catastrophic）与 G2b（degraded）两条 HARD 判据恒真通过**。这是 D-38「恒真的判据等于没有判据」的**同类复发**，发生在 `--reuse` 通路。

**修法**（`tools/acceptance.py` + `tools/r151_shape_accept.py`）：

| 项 | 修前 | 修后 |
|---|---|---|
| 无 health 的 rows | 两条判据报 **PASS**（恒真） | 两条判据 **SKIP + 显式 WARN**（并打印告警文本与替代 json 名） |
| 结论标签 | `PASS(hard)` | `PASS(hard, N 判据跳过——不可视为完整验收)` |
| 退出码 | 0 | **2**（0=全 PASS / 1=有 FAIL / **2=判据被跳过**） |
| `summarise()` | 静默 0 计数 | 增 `n_health_rows` / `health_available` 两字段 |
| json 的 `hard[].pass` | `bool(None)` ⇒ false | 保留 `None`（区分"跳过"与"失败"） |

**实测**：

```
$ python tools/acceptance.py --reuse runs/r151_shape_baseline.json ; echo $?
  [WARN] rows 缺 health 字段（0/86 行有 health） ⇒ G2/G2b 判据**跳过**（不判定 PASS/FAIL）。
  [SKIP] G2 新发 catastrophic=0                   SKIP（rows 无 health 字段，判据不成立）
  [SKIP] G2b degraded 计数（基线 9）                  SKIP（rows 无 health 字段，判据不成立）
  结论：PASS(hard, 2 判据跳过——不可视为完整验收)
2

$ python tools/acceptance.py --reuse runs/r156_acceptance.json ; echo $?
  [PASS] G2 新发 catastrophic=0   0 新发（名单 [37, 50, 51, 91]，已登记 [37, 50, 51, 91]）
  [PASS] G2b degraded 计数（基线 9）  5 <= 9
  结论：PASS(hard)
0
```

### 3.2 修法：让判据感知 basic 分支是否被修正（而非拍阈值）

R148 的判据 2 把两件事混为一谈：
**(a)** pH 越 7 = 进入 basic 分支（只说明进入过）；**(b)** basic 分支是**数值病态**的

R156 证明 (b) **可以被消除**：`ph_fix=1` 链式法则修正后 5 批钳位批 pH_max 9.19→7.07、**钳位 5→0**，
且 86 批产量仍 86/86 在 ±5%、catastrophic 4→0、P relRMSE max 0.848→0.430 ⇒ **越 7 在修好的分支里无害**。

**新判据**：

```
invalid ⇔ 钳位（[H⁺] ≤ 0，数值崩溃）
        OR 越域幅度 ph_max_pre ≥ ph_hard
其中 ph_hard 由 sim.attrs["ph_basic_fixed"]（= ph_fix）自动决定：
  ph_fix=0（默认，basic 分支病态）⇒ ph_hard = 7.0 ⇒ **与 R148 旧行为逐位一致**
  ph_fix=1（basic 分支已修）       ⇒ ph_hard = None ⇒ 越 7 只报告、不判 invalid
```

**同时新增分布字段**（D-44 教训）：`n_steps` / `over7_frac` / `ph_hard_max_used` / `basic_branch_fixed`，
并区分两条 flag：「越域且数值病态（判 invalid）」vs「越 7 但 basic 分支已修（**不判 invalid**，仅登记）」。

## 四、T2-1 / D-57 —— 双稳态的连续旋钮搜索

### 4.1 判据（四版演进 + 区间收缩诊断）

阶段 0 粗扫 9 档找最大相邻跳变 → 阶段 1 **二分**把跳变区间逼到极限窄 → 区间内 **16 点密采样**算相邻最大跳变。
**另加一路**：粗区间**直接密扫**（`--dense-coarse`）—— 因为单调光滑响应**根本不能用二分**。

**判据经四版修正，前三版的结论全部作废（D-69）**：

| | v1（作废） | v2（作废） | v3 | **v4（现行）** |
|---|---|---|---|---|
| 二分更新规则 | `if abs(ym-ylo) <= abs(yhi-ylo)` | `if ym < (ylo+yhi)/2` | **锚点夹逼**：`dA=|ym−yA|` < `dB=|ym−yB|` ⇒ `lo=mid` | 同 v3 |
| 缺陷机理 | 近 100 pp 跳变时 `<=` 平局把高端中点**错记到低端** ⇒ 区间塌陷到单一分支 | 对**单调光滑**响应收敛到「**响应取中值处**」而非跳变处 ⇒ 区间里根本没有跳变 | — | — |
| 不变量 | 无 | 无 | **区间始终同时含跳变两侧**（锚点 = 粗扫两端响应且固定不移动）⇒ 收敛到**跳变位置本身** | 同 v3 |
| 判定主证据 | 密采样最大相邻跳变 | 区间响应跨度的收缩率 | 同 v2 | **三态**：CONTINUOUS（最大相邻 < 5 pp）/ DISCONTINUOUS（≥ 5 pp）/ **ERRATIC**（差分变号 ≥ 3 次 ⇒ 混沌窗） |
| 补充路径 | — | — | — | **粗区间直接密扫**（`--dense-coarse`）—— 判单调光滑型旋钮的唯一可行路径 |

**自证伪过程**（这是本轮最值得记的一步）：
v1 报 `sd` 为 **CONTINUOUS**（细化最大相邻 0.00 pp）。但**工具自己的数据否定了它** ——
二分把区间收敛到 `[0.00149951, 0.0015]`，而该区间 32 个密采样点**全部**在高端（−0.151%…−0.148%），
说明**跳变根本不在区间内** ⇒ 区间没夹住跳变 ⇒ 判定无效。
修正二分器后重跑冒烟（`sd`，4 次二分）：区间内响应跨度序列 **99.85 → 99.85 → 99.85 → 99.85 → 99.85**，
**收缩比 = 1.0** ⇒ 跳变不随区间收窄而消失 ⇒ **真阶跃** ⇒ `sd` 改判 **DISCONTINUOUS**。
v2 又暴露第二形态：`kdeg`/`muhs` 的跨度收敛到 20.01→0.00 / 73.90→0.00（**假收缩**）⇒ 改锚点夹逼。
v3 仍漏判混沌：`muhs` 跨度收敛到 0.65 pp 看似连续，但密采样显示 −36.77/−56.24/−36.90/−41.92/−55.54…
（**相邻 19.47 pp、差分变号 12 次**）⇒ 补 `ERRATIC` 分支。

> **纪律**：**自建判据必须先做证伪测试**。光看「判据输出」不足以相信判据，必须检查**判据自身的中间量**是否自洽。
> 这是 D-38「恒真的判据等于没有判据」的**第三种形态**：判据不是恒真，而是**被一个平局 bug 恒定地导向同一个答案**。
> **追加**：判据必须覆盖"第三种响应"（混沌窗），否则会被静默误判为 CONTINUOUS。

**形式判据达成，但实质结论是「否定」**：

- `kdeg` 满足 R156 设的形式判据（响应不连续度 < 5 pp），**D-57 的形式问题有解**。
- **但它不是"解锁产素启动"的旋钮** —— `kdeg` 是**单调的降解旋钮**：它把整条轨迹（产量、峰值）按比例压低
  （0 → −73.47%，P_max 32.685 → 13.652），**不能**把系统从崩塌态（−100%）连续地拉回生产态。
- 真正的双稳态墙在 `sd` / `meanP` / `Ysp` 三个方向上，**全部是硬阈值**（`Y_sP` 跳变点 **0.894344**，
  `sd` ≈ 0.0014995，`meanP` ≈ 0.001995）⇒ **进料可行域的硬约束是阈值型的，不是参数型的**。
- ⇒ **D-54（葡萄糖闭环）在"靠参数旋钮解锁"的路线上**：**运行期连续调控永久关闭**；开环设定点重整定仍可行但降级为**一次性标定**（详见 §4.6 判决性实验）；
  若要运行期调控，只能走**结构改动**路线（引入残糖反馈 / 改变门控机制本身），属 L3，需另行授权。

#### 判决性结论（**推翻了本轮自己的预判**）

上一轮留下的假设是「若全部无效 ⇒ 崩塌态是吸引子（basin）」。**实测否证了这个假设**：

1. **崩塌态不是吸引子** —— `sd` 与 `meanP` 都能把系统从崩塌态拉回生产态（+1.33% / +0.51%，`valid=True`）。
   ⇒ 崩塌态是**阈值隔离的深盆地**：可以被**跨出去**，但只能**跨**。
2. **但没有任何旋钮能连续地走回** —— 两个能逃逸的旋钮响应是**阶跃**（区间响应跨度恒 **101.33 / 100.51 pp**，收缩比 **0.967 / 1.01** ⇒ 跳变不随区间收窄而消失）；
   两个**连续**的旋钮（`kdeg` / `muhs`）则**全程滞留在崩塌态**（产量恒 −100%、`valid=False`）。
   ⇒ **「连续」与「能走到目标」是两件事**：形式判据达成 ≠ 实质可用（这是本轮 §4.5 的第二次印证）。
3. **逃逸的工程代价（决定性量级）**：
   - `sd` 跳变窗口宽 **2.44e−07**（相对宽度 **1.6e−04**）⇒ 设定点相对精度需 **1e−04** 量级；
   - `meanP` 跳变窗口宽 **2.44e−08**（相对宽度 **1.2e−05**）⇒ 需 **1e−05** 量级；
   - 实务分辨率下（粗扫档位）：`sd` 需 0.0015 → 0.0025（**+67%**）、`meanP` 需 0.002 → 0.0021（**+5%**）。
   ⇒ 这不是「调参」，是**标定级精度**的一次性设定点重整定。
4. ⇒ **D-54 的结论要精确化（不是"封死"，是"降级"）**：
   - ❌ **运行期连续调控（梯度型闭环）在这套方程里不可行** —— 响应是阶跃，跳变两侧的梯度信号无可用区分度，控制律跨不过去；
   - ✅ **开环设定点重整定可行**（把 `sd` 或 `meanP` 重新标定到阈值另一侧），但精度要求 1e−04…1e−05 相对 ⇒ 属**标定**而非**控制**；
   - ⇒ 「靠参数旋钮解锁」**不是完全封死**，而是被降级为「**一次性标定**」而非「**运行期调控**」；
     若要运行期调控，只能走**结构改动**路线（引入残糖反馈 / 改变门控机制本身），属 L3，需另行授权。

> **方法论收获**：判决性实验的价值恰恰在于**它可能否证自己的预判**。若本次只做"三旋钮全无效"就下"崩塌态=吸引子"的结论，
> 台账与后续路线都会建立在一个**过强**的否定结论上（进而误判"结构改动是唯一出路"）。
> ⇒ 纪律追加：**预判式结论必须留一个专门的证伪位**，且**证伪位被触发时必须改写结论，不得事后合理化**。

### 5.2 T3-2：模式级故障注入仿真 ★新增

**动机**：R127 的三个算子（降 KLa / 注酸 / 减喂食）幅值是**常数**、只有时间窗一个形状维度 ⇒ 只能表达**阶跃型**故障；

#### 5.2.2 两条方法论发现（本轮新增债 D-67 / D-68）

**① 默认基线下的故障注入会被 pH 数值病态淹没（D-68）**
b22 在默认基线上跑 5 个引擎侧模式，**每个故障臂的 `pH_min` 都掉到 3.000**（守卫钳位）⇒ 轨迹被 D-55 的
basic 分支病态拖垮。**b3 也一样**（3 臂钳位）⇒ **这不是 b22 特有，是任何把 pH 推过 7 的扰动的通病**。
⇒ 修法：① 工具加 `--ph-fix`；② 新增**数值污染前置判据**
`numerically_contaminated = (故障臂 pH 钳位数 > 基线 pH 钳位数)`，受污染臂打 `⚠ 数值污染` 标记；
③ **故障特征级仿真必须在 `ph_fix=1` 口径下做**。

**② 故障签名必须分段（窗内 / 恢复期），整批口径会被恢复效应主导（D-67）**
`feed_hold` 的 `S_max`：基线 **3.68 g/L** → 故障 **21.10 g/L**（**升高**），与"少喂 ⇒ 残糖低"的朴素期望相反。
机制：故障窗内进料被切 ⇒ 产物/生长停；窗末恢复进料，但**菌体已被打残** ⇒ 恢复期**消耗低于进料** ⇒ 残糖累积。
**第一次修法（改成窗内 `S@窗末`）同样不成立** —— b22 的残糖在窗内**已贴模型地板**（基线 0.001395 vs 故障 0.001424 g/L）
⇒ **窗内 S 无判别力**（与 D-53「残糖结构性不可辨识」同向）。
⇒ 最终判据取机制上成立的两条：`p_max` **down**（产物必降）+ 整批 `s_max` **up**（恢复期欠消耗）。
工具因此新增三个**窗口内**特征量 `s_at_window_end` / `p_at_window_end` / `do2_at_window_end` 并逐条打印。

#### 5.2.3 结论

- **能力已建立**：模式级（渐变）故障注入 + **传感器侧故障**两条通路都能跑，**方向签名 7/7 全部与物理预期一致**。
- **传感器侧故障不改动力学**（`max|Δ| = 0` 逐位一致），只污染观测通道副本 ⇒ 可用于回答
  "故障能否被现有观测手段辨识"，而不会污染动力学结论。
- **前置条件（硬）**：故障仿真**必须**在 `ph_fix=1` 口径下做；默认基线的结果**不可作为故障特征证据**。
- **未做**：故障幅值与真实事件的对应（需要事件记录）、多批次规模化（本轮只跑 b22/b3 两批）。

## 八、本轮踩到的坑（供后续轮次）

1. **heredoc 会破坏 `\r\n`** ⇒ `state.yaml`（纯 CRLF）的锚点替换在 heredoc 里连续失败两次；
   **一律用 Write 落 .py 脚本再执行**（`tools/r157_state_update.py` 即为此而写）。
2. **`state.yaml` 的 `cap.reasons` 是 flow sequence** ⇒ plain scalar 里**不能出现方括号/ASCII 逗号**
   （`d[H⁺]/dt`、`dy[6]`、`u∈{...}`、`σ_pop(mux)≤0.0328 / mup≤0.0056` 里的逗号都会让 YAML 崩）。R153 已踩过一次，本轮又踩。
3. **Windows multiprocessing 用 spawn** ⇒ `python - <<EOF`（`__main__` = `<stdin>`）会让 `ProcessPoolExecutor` 直接崩
   （`OSError: Invalid argument: '<stdin>'`）⇒ 池化工具**必须以文件方式运行**。
4. **前台 bash 2 分钟超时会被 SIGTERM**（不是 `timeout` 语义）⇒ 长任务一律后台跑；且 `tail` 管道会让 `$?` 取到 `tail` 的退出码，
   验退出码必须脱离管道。
5. **`n_steps` 不是常量**（1049–1289）⇒ 任何"步数"判据都必须**归一化**并**报分布**。
6. **覆盖率是可平凡满足的指标** ⇒ I3 类判据必须同时约束**区间宽度**，否则"区间开到 ±98% 也算达标"。
7. **`mu_h`（par[19]）在 `inhib_flag=2` 分支被 `k4·par[18]` 覆盖** ⇒ 对 86 批绝大多数无效；有效旋钮是 `mu_h_scale`（par[18]）。
8. **V3 的连续 S/DO2/P/OUR/CER 是参考模型输出，不是化验** ⇒ 拿它们当软测量的"真值"是**循环论证**；
   合法的软测量目标只有稀疏离线化验列（X/P/PAA/NH3/Viscosity）。
9. **改函数签名/调用链后，新参数要在四处全部打通**：`--base-override` 打通时只改了调用点、没改 `_bisect` 签名 ⇒
   `NameError: name 'extra' is not defined` ⇒ 漏了**函数签名、调用点、批量 job 构造、refine 密采样**四处中的后两处。
10. **pytest"疑似挂起"的定位顺序**：先 `--collect-only`（1.63 s / 13 collected ⇒ 收集正常 ⇒ 挂在执行阶段），
    再看进程 CPU（**0.015 s** ⇒ 阻塞在极早期而非计算中）⇒ 判为**偶发环境问题**，重跑即可（**13 passed in 422.11s**），
    **不要**因此改代码。
11. **YAML / markdown 表格的字符陷阱**：block sequence 的 plain scalar 里禁止半角逗号 / 方括号 / 花括号 / 半角冒号+空格 / 半角 `#`
    （`state.yaml` 的 `cap.reasons` 是 flow sequence，规则更严）；markdown 表格行内容体内禁止裸 `|`（会破坏列结构）
    ⇒ 回填脚本必须**内置字符校验**，否则 YAML 直接解析失败 / 表格错位。
12. **幂等指示要区分 `[skip]` 与 `[notfound]`**：锚点被替换后旧锚点消失，复跑若只报 `notfound` 会让人误以为条目丢失
    ⇒ 应额外检测"新文本是否已存在"并报 `[skip]`。
