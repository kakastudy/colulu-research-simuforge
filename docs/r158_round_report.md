## 二、消融口径：本轮的方法论主线

R120 的双批消融给了「PAT 转发对引擎 PAA 动态几乎无损（fidelity r≈0.9995），触发批上 fused 锚定层把
r 从 0.35 拉到 0.81」这样的结论。本轮要把它放大到 86 批并**做成可交付的判据**，
因此必须先处理三个陷阱。**这三个陷阱都是本轮实测发现的，不是推演出来的。**

### 2.1 陷阱①：PLS 资产的输出单位不是 mg/L（本轮新发现）

**实测**（`tools/r158_raman_unit_probe.py`，用 V6 `.mat` 的 **Batch_01 真实存储谱**，
非合成谱，因此不含合成层的任何偏差）：

```
PLS(stored spectra) -> PAA_pred: min 0      max 2.113
化验 PAA_offline           : min 430.4  max 2023     (mg/L)
OLS: lab(mg/L) = 721.263 * pred + 404.644     (r = 0.8463, R² = 0.72)
```

⇒ `predict_paa()` 的输出单位与 mg/L **差约 1000 倍**。

**为什么此前没被发现**：R120 的三重验证（0.9995 / 0.9997 / 0.8463）**全部是相关系数**，
而**相关系数对线性缩放完全不变**。形式化演示（本轮工具内建）：

```
r(pat, enginePAA) = 0.9291      scale ratio = 930.6
pat × 1000 后的 r = 0.9291      （与原始逐位相同）
```

⇒ 「保真度 r=0.9995」这条结论**不能作为「量纲正确」的证据**。
这是 D-69「判据自身的证伪测试」纪律的**又一个实例**，也是 D-38 的第四种形态：
**判据不是恒真，而是恒定地漏掉某一类缺陷（缩放不变 ⇒ 量纲类缺陷全部隐身）**。

**处置**：本轮所有**绝对量**指标一律先过标定（乘资产级常数 721.263 或按批 OLS），
并把「量纲」登记为独立债务（**D-70**）。

### 2.2 陷阱②：锚定层在锚点必然贴化验 ⇒ 覆盖率是平凡满足指标

`raman_pat_channel.build_pat_channel` 的锚定修正层是**按构造**做比例校正的
（`fused = pat × lab_i / pat_i`）⇒ 在锚点处 `fused` 必然等于化验值。
若用「锚点处覆盖率」当判据 ⇒ **恒真**（D-38 的形态）。

**处置**：引入 **留一锚点交叉验证（LOOA, leave-one-anchor-out）** ——
每个锚点用它**以外**的锚点构建融合层，再预测该锚点 ⇒ 度量的是**锚点之间的外推能力**。

### 2.3 陷阱③：改善可能来自「用了化验锚点」这一共同项，而非 PAT 通道

LOOA 之后 C 口径的 nRMSE 从 29.6% 降到 10.5%，看起来是巨大胜利。
但**引擎 PAA 用同样的锚点做同样的锚定，也会大幅下降** ⇒ 必须设对照。

**处置**：本轮设 **3 个控制组** + **1 个平凡上界**：

| 组 | 构造 | 作用 |
|---|---|---|
| **A** 引擎直报 | 引擎 PAA vs 化验 | 基线 |
| **A2** 引擎 + 两点校准 | 对引擎 PAA 做**留一锚点**的仿射校准（斜率+截距，**完全不用 PAT**） | **判定「改善是否只来自校准」的关键对照** |
| **B** PAT 转发 | PAT 读数（标定后）vs 化验 | 前向通道的无锚定信息量 |
| **C** PAT + 锚定（LOOA） | 留一锚点的融合估值 | 锚定层的真实外推增益 |
| **C0** 引擎 + 锚定（LOOA） | 同样锚点，但**锚在引擎 PAA 上** | **判定「C 的收益是否来自锚定技巧本身」的关键对照** |
| **C1** 直接插值化验值 | 只用化验值线性插值（不看 PAT、不看引擎） | **平凡上界**（锚定这件事本身的极限） |

### 2.4 门④：独立信息的严格判据（增量信息检验）

「PAT 与引擎 PAA 相关 r 很高」不足以判定 PAT 无信息（允许高相关但仍带独立成分）。
本轮用**控制引擎 PAA 后的增量信息检验**：

```
y ~ a + b·engine_PAA + c·PAT     ⇒   ΔR² = R²_full − R²_eng_only，  c 的 t 统计量
```

显著性判据：**|t| ≥ 2 的批次占比 ≥ 5%**（单看 ΔR² 会被大 R² 批的噪声放大）。

### 3.1 全池汇总（`runs/r158_pat_ablation_scale.json`）

| **A2** 引擎 + 两点校准 | **13.07%** | 0.26% | 29.56% | — | — |
| **B** PAT 转发 | **32.14%** | 19.97% | 45.05% | 0.609 | 10.24% |
| **C** PAT + 锚定（LOOA） | 10.55% | 7.00% | 21.93% | 0.918 | 4.37% |
| **C0** 引擎 + 锚定（LOOA） | 11.43% | 6.69% | 27.93% | 0.909 | — |
| **C1** 直接插值化验值 | 5.88% | 0.28% | 12.61% | — | — |

循环性 / 增量信息：

| 量 | 中位 | 说明 |
|---|---|---|
| `pat_vs_engine_r` | **0.9796** | PAT 几乎是引擎 PAA 的重命名 |
| `incr_r2_pat_added` | **0.0199** | 控制引擎 PAA 后 PAT 的增量 R² |
| `incr_t_pat` | **0.104** | PAT 系数 t 值（**不显著**） |
| \|t\| ≥ 2 的批次 | **19 / 86** | 22%，未达 95% 置信的 5% 门槛的**反向**——仅约 1/4 批次显著 |

### 3.2 分层结果（**本轮的核心发现**）

按「引擎 PAA 与化验的批内相关 `A_engine_r`」分层：

| 层 | n | A nRMSE | B nRMSE | A2 nRMSE | C nRMSE | C0 nRMSE | 符号检验 |
|---|---|---|---|---|---|---|---|
| **失真批**（`A_r ≤ 0.5`） | 41 | 41.77% | 31.90% | **0.49%** | 11.23% | 13.59% | B>A **38/41**, p=1.05e−08 |
| **可信批**（`A_r > 0.5`） | 45 | 22.95% | **32.39%** | 16.60% | 9.27% | 9.44% | B>A **13/45**, p=0.0066（**方向相反**） |

**关键读法**：

1. **失真批上 B（PAT 转发）确实优于 A**，符号检验 p=1.05e−08，方向明确。
   ⇒ PAT 通道**在引擎 PAA 失真场景下有实用价值**（这是 T3-3 的正面结论）。
2. **但 A2（只做两点校准的引擎 PAA）在失真批上中位仅 0.49%**，
   远优于 B 的 31.90% 与 C 的 11.23%。
   ⇒ 失真批的「引擎 PAA 失真」本质是**两点可校准的偏置/斜率差**，
   **不是不可辨识的失真**；PAT 通道**不是最优解**。
3. **失真批上 C 系统性劣于 C0**（41/41，p=9.1e−13）⇒
   把锚点用在 PAT 上，**比用在引擎 PAA 上更差** ⇒ 锚定修正层**不交付**。
4. **可信批上 B 显著劣于 A**（13/45）⇒ PAT 通道在引擎可信时**纯属噪声与失真**。

### 3.3 触发批（μp > 0.055，10 批）

| 口径 | nRMSE 中位 |
|---|---|
| A 引擎直报 | 46.98% |
| B PAT 转发 | 42.18%（B 优于 A：**8/10**） |
| A2 引擎 + 两点校准 | 25.61% |
| C PAT + 锚定（LOOA） | 15.25% |

但 C 仍劣于 C0 ⇒ **锚定层的实现方向是错的**（应锚在引擎 PAA 上，不是 PAT 上）。

## 四、判决

### 4.1 三口径判决

| 口径 | 判决 | 依据 |
|---|---|---|
| **B（PAT 转发）** | ❌ **全池 NOT_IDENTIFIABLE** | 门①未过（全池 32.14% 劣于 A 的 29.62%）；门④增量 R² 0.0199 / t 0.104 不显著 |
| **B 分层** | ⚠️ **失真批 MARGINAL / 可信批 NOT_IDENTIFIABLE** | 失真批 38/41 优于 A（p=1.05e−08）；可信批 13/45（方向相反） |
| **C（PAT + 锚定）** | ❌ **NOT_IDENTIFIABLE** | 门④：相对 C0 净增益仅 0.88 pp（全池）；失真批上 **系统性劣化**（41/41，p=9.1e−13） |
| **锚定修正层本身** | ❌ **不交付** | 门⑤：接近 C1 平凡上界（5.88% vs C 的 10.55%）但**劣于更简单的 C0** |

### 4.2 结论

1. **Raman/PAA-PLS 通道不作为交付组件引入**（`cap` 口径不变，仍为 L2 prototype conditional）。
2. **唯一可保留的正面结论**：PAT 通道在**引擎 PAA 失真批**上相对引擎直报有统计显著的改善
   （38/41，p=1.05e−08）。但它**不是最优解**——两点校准（A2，中位 0.49%）在同场景下严格更好，
   且**不需要 Raman 资产、不需要 PLS、不需要光谱合成**。
   ⇒ 若未来要处理失真批，**优先做两点校准，而非引入 PAT**。
3. **PAA 锚定修正层须改向**：现有实现锚在 PAT 上，实测**系统性劣于**锚在引擎 PAA 上
   （失真批 41/41 劣化）。修正方向：**锚在引擎 PAA 上**（即 C0 口径），可作为 V1+ 的候选改进，
   但本轮**不做**（属 L3 级结构改动，需另行授权）。
4. **R111「PAT 是忠实转发 + 条件锚定」的结论在全池得到确证**：
   `pat_vs_engine_r` 中位 0.9796、增量 R² 0.0199、t 0.104 ⇒ PAT **不含独立信息**。

### 4.3 明确不做

- 不把 PAT 读数反向接入引擎 ODE（观测分离原则，`docs/raman_pat_integration_spec.md` §4）。
- 不在批 80 退化化验上做单点合格。
- 不因失真批的 B>A 而宣称 PAT 通道可交付（被 A2 严格支配）。
- 不修改 `raman_pipeline.py` / `raman_pat_channel.py` 的量纲口径（**登记为债务 D-70**，不在本轮静默改动）——
  改动会影响 R50/R53/R81/R103/R110 的历史数值可比性。

### 5.3 判定纪律的三条延伸（本轮沉淀）

1. **相关系数不是量纲的证据** —— 任何「保真度 / 一致性」类指标必须**同时**报绝对量或尺度比。
2. **覆盖率类指标必须做抗平凡满足检验** —— 锚定/拟合类构造会让锚点处指标恒真 ⇒ 必须留一交叉验证。
3. **任何「改善」都必须配一个「同样输入、更简单方法」的控制组** ——
   否则会把校准的功劳记到被评估对象头上（本轮 A2 / C0 两个控制组各推翻了一个初判）。
