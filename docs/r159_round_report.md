## 零、本轮一句话

> **R158 的「唯一正面结论」被撤回。**
> R158 报告「失真批上两点校准（A2）中位 **0.49%**，严格支配 PAT 转发（31.90%）⇒ 处理失真批应优先做两点校准」——
> 这个结论**不成立**，因为：
> ① 所谓「失真批」（`A_engine_r ≤ 0.5`，n=41）里 **29 批的化验 PAA 值被钉死在 ~1200 mg/L**（CV < 0.5%，
>    动态范围仅 17.8 mg/L）—— **化验信号退化**，不是「引擎失真」；
> ② 在这些退化批上 **A2 退化为「预测一个常数」**（拟合斜率中位 **0.0010**、预测动态范围 **0.072%**），
>    连**常数基线**都打不过（37/41 批更差，p=1.03e−07）⇒ 0.49% 是**平凡满足**，不是校准能力；
> ③ **剔除退化批后**（n=57 有信息批），A2 中位 **20.47%** **劣于** C0（逐点比例锚定）**10.29%**
>    ⇒ 「A2 严格支配」**方向反转**；
> ④ 真正的失真批（有信息且 r ≤ 0.5，n=12）上，A2 **30.48%** 甚至**劣于常数基线 28.64%**。
>
> **同时，R158 的主判决被加固**：PAT 无独立信息（D-71）不仅成立，剔除退化批后**更强**
> （增量 R² 0.0199 → **0.0092**、t 0.104 → **0.036**）。
>
> ⇒ **D-71 / D-72 / D-70 三条维持；R158 的「唯一正面结论」升格为新债务 D-74；化验退化区升格为 D-73。**

## 一、为什么必须做这一轮

R158 的报告写得很干净，结论也标了「唯一可保留的正面结论」。但**同一张表里有两个数字放在一起不该被放在一起**：

| 量（R158 失真批 n=41 中位） | 值 |
|---|---|
| `A_engine_r`（引擎 PAA 与化验的批内相关） | **0.0518** |
| `A2_looa_nrmse`（两点校准的误差） | **0.49%** |
| `C1_looa_nrmse`（**直接插值化验真值**的平凡上界） | **0.57%** |

一个只用**引擎读数**的预测器（0.49%），**优于直接拿化验真值插值**（0.57%）—— 这在数学上不可能同时成立，
除非其中之一是平凡的。

而 R158 自己在 §4.3 写下过一句「**不在批 80 退化化验上做单点合格**」——
说明**单批退化当时已被察觉**，但**没有推广到全池**，也**没有在统计口径上排除**。
这是 D-38「恒真的判据等于没有判据」的**第五种形态**：不是判据恒真，而是**判据在一个恒真的子集上做统计**。

> **纪律**：R157 刚沉淀了「预判式结论必须留专门的证伪位，证伪位被触发时必须改写结论、不得事后合理化」。
> 本轮就是这个证伪位被触发的时刻 —— **R158 的正面结论被自己的后续轮次推翻**，而不是被"补充说明"软化。

## 二、方法：五道证伪门 + 一个有效口径重判

工具 `tools/r159_a2_falsification.py`，86 批（`GOLDEN_ALL`，与 R158 **完全同口径**），
复算 R158 的关键量**逐位一致**（失真批 n=41、`A_engine_r` 中位 0.0518、A2 中位 0.49203788267713794
vs R158 的 0.49203788267713794）⇒ 口径对齐、可直接比较。

### 2.1 五道门

| 门 | 检验内容 | 触发判据 |
|---|---|---|
| **G1** | **化验信号退化度**：失真批的化验 CV 是否远低于可信批？ | `CV_失真 < 0.25 × CV_可信` |
| **G2** | **常数预测基线**（控制组）：「留一锚点的化验均值」当预测器，误差多大？ | `A2 / 常数基线 ≥ 0.8` ⇒ 无净贡献 |
| **G3** | **A2 的斜率可辨识性**：拟合斜率是否 ≈ 0？预测动态范围是否远小于化验动态范围？ | 斜率 ≈ 0 **或** 预测动态范围 < 化验动态范围的 50% |
| **G4** | **时间因果性**：LOOA 用**全部其余锚点**（含未来）拟合；改用「只用 t 之前的锚点」的前推式后优势是否还在？ | 前推式下 `A2 / 常数基线 ≥ 0.8` |
| **G5** | **在线可得性**：分组标签 `A_engine_r` 本身需要化验值才能算 ⇒ 部署时不可得 | 恒触发（结构性） |

> **G2 的意义**：它就是 R158 自己立的纪律③「任何『改善』都必须配一个『同样输入、更简单方法』的控制组」的应用 ——
> 只是这次更简单的那个方法是「输出一个常数」。

### 2.2 有效口径重判（第六段）

退化判据：**化验 CV < 2%**（化验值无动态信息）⇒ 全池 **29 批**（61–90 区间，缺 b81）。

三组重判：
- **有信息批**（CV ≥ 2%，n=57）
- **退化批**（CV < 2%，n=29）
- **真·失真批**（有信息 **且** `A_engine_r ≤ 0.5`，n=12）—— 这才是「引擎 PAA 失真」的真实样本

## 三、实测结果（86 批，exit 0）

### 3.1 五道门：**四门触发 + 一门结构性触发**

| 门 | FIRED | 关键数字 |
|---|---|---|
| **G1 化验信号退化** | ✅ | 失真批化验 CV 中位 **0.4568%** vs 可信批 **56.6742%** ⇒ 比值 **0.0081**（退化 124 倍） |
| **G2 常数基线** | ✅ | 失真批 A2 **0.4920%** vs 常数基线 **0.4854%** ⇒ 比值 **1.014**；符号检验 **37/41 批 A2 更差**，p=**1.03e−07** |
| **G3 斜率退化** | ✅ | 拟合斜率中位 **0.0010**（≈ 0）；A2 预测动态范围 **0.0720%** vs 化验动态范围 **24.50 mg/L** |
| **G4 时间泄漏** | ✅ | 前推式（只用过去锚点）下 A2 **0.6461%** vs 前推常数 **0.6147%** ⇒ 比值 **1.051**；**9/41 批反向**（A2 更好，p=4.3e−04，但幅度仅 0.034 pp） |
| **G5 在线可得性** | ✅ | 分组标签 `A_engine_r` 需化验值；A2 本身也需化验锚点 ⇒ 只能作「离线锚定 + 在线外推」 |

**综合判决**：`A2_NOT_MEASURABLE（至少 4 道门触发）`

### 3.2 剔除退化批后的重判 —— **结论方向反转**

| 指标（中位，%） | **有信息批 (n=57)** | **退化批 (n=29)** | **真·失真批 (n=12)** |
|---|---|---|---|
| `A_engine_r` | 0.9204 | 0.0254 | 0.1826 |
| 化验 CV (%) | 43.78 | **0.29** | 27.05 |
| 化验动态范围 (mg/L) | 3166.6 | **17.8** | 1233.9 |
| A 引擎直报 nRMSE | 25.60 | 37.80 | 49.81 |
| **A2 两点校准 nRMSE** | **20.47** | **0.31** | **30.48** |
| **G2 常数基线 nRMSE** | 46.22 | **0.30** | **28.64** |
| **C0 逐点比例锚定 nRMSE** | **10.29** | 13.59 | **13.54** |
| A2 前推式 nRMSE | 20.81 | 0.40 | 28.67 |

| A2 预测动态范围 (%) | 41.93 | **0.04** | 5.69 |

**符号检验**：
- 有信息批 A2 vs 常数基线：**10/57** 更差（Δ 中位 **−25.94 pp**，p=**7.51e−07**）⇒ A2 **确实**优于常数基线（方向为正），但幅度有限。
- 有信息批 A2 vs **C0**：**50/57** 更差（Δ 中位 **+7.65 pp**，p=**4.24e−09**）⇒ **A2 系统性劣于 C0**。
- 真·失真批：A2 **30.48%** **劣于** 常数基线 **28.64%** ⇒ A2 在真失真批上**无净贡献**。

**剔除后判决**：
> **`A2_RETRACTED`** —— 剔除退化批后 A2 中位 **20.47%** **劣于** C0 中位 **10.29%**
> ⇒ R158 的「A2 严格支配」结论**撤回**。

### 3.3 退化批的成因（全 100 CSV 普查）

对 `data/processed/batches/` 全部 100 个 CSV 扫 `PAA_offline`（`time_h > 20`）：

- **批 61–90（共 30 批，b81 无 GOLDEN_ALL 缓存）全部退化**：化验值均值 **1198.6–1205.0 mg/L**、
  CV **0.13%–1.85%**、动态范围 **6.7–102.4 mg/L**。
- 而批 1–60 化验 PAA 是正常动态（CV 中位 **43.8%**、动态范围 **3166.6 mg/L**）。

⇒ **批 61–90 是 V6 数据集的后 30 批，其 `PAA_offline` 列是占位/合成值（钉在 ~1200 mg/L）**，
不是真实 PAA 动态。**这是一处此前从未登记的数据缺口**（D-73）。

### 4.2 「处理失真批应优先做两点校准」这条**操作建议的修正**

R158 的建议是：「若要处理失真批，优先做两点校准，而非引入 Raman 资产」。

R159 的修正：
1. **「而非引入 Raman 资产」这半句成立** —— PAT 仍无独立信息（D-71），**不引入**的决定不变；
2. **「优先做两点校准」这半句不成立** —— 两点校准在真失真批上（n=12）**劣于常数基线**（30.48% vs 28.64%）、
   且**系统性劣于更简单的逐点比例锚定 C0**（全有信息批 50/57，p=4.24e−09）；
3. ⇒ 正确表述：**失真批的 PAA 估值问题目前**没有**已验证的简单解**。
   C0（锚在引擎 PAA 上的逐点比例锚定）在有信息批上中位 **10.29%**，
   是当前**最好的候选**，但它**仍需化验锚点**（⇒ 只适用于有离线化验的批次），
   且**尚无在线可得的失真判别器** ⇒ 属 **V1+ 候选**，不是可交付组件。

## 五、本轮沉淀的纪律（新增两条）

1. **统计口径必须先做「信号退化筛查」** —— 任何以化验/真值为分母或对照的统计，
   必须先验证**真值本身有动态信息**（CV / 动态范围）；否则结论会落在**真值恒定**的子集上，
   而这类子集会让**任何**预测器的误差都趋近 0 ⇒ 结论**必然**平凡满足。
   本轮的表现形式：29 批退化批让一个"预测常数"的基线拿到 0.30%，
   比最好的模型还好 ⇒ **模型排名被真值退化翻转**。
2. **结论的证伪位必须由后续轮次真的执行** —— R158 给出了正面结论，
   R159 把它推翻；**这本身不是 R158 的错误，而是流程奏效**。
   ⇒ 台账上「正面结论」与「否定结论」享有**同等**的被证伪义务；
   不得因为正面结论"更可用"而给予更宽松的复核标准。

## 六、工程坑（本轮实际踩到）

- **Windows 下 `python` 与 `py` 是两个解释器**：`python` 是 WorkBuddy 自带的 3.13.12（**无 numpy/pandas/scipy**），
  `py` 是 Python 3.10.4（numpy 1.26.4 / pandas 2.3.3 / scipy 1.15.3）⇒ **本项目所有脚本必须用 `py`**。
  （前几轮的脚本若用 `python` 跑会直接 `ModuleNotFoundError`。）
- **字典字面量里不能混写条件表达式作为值**：`{"k": X if cond else Y}` 在 `X` 含逗号时会被解析成 tuple ⇒
  必须先算好再放进字典，或用括号包住整个条件表达式。
- **`--batches all` 与逗号列表分支的判断顺序**：先判 `== "all"` 再判 `split(",")`，
  否则 `"all"` 会进 `int()` 抛 `ValueError`。
- **`summary["verdicts"]` 的初始化位置**：把判决字典从字面量里挪出来做增量赋值时，
  必须确认**初始化仍在** —— 否则 `KeyError: 'verdicts'`。
