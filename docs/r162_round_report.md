## 二、oq#38：终末收获口径 —— 定案并关闭

### 2.1 MATLAB 原式（`indpensim_run.m:194-196`）

```matlab
Xref.Stats.Penicllin_harvested_during_batch = sum(Xref.Fremoved.y .* Xref.P.y)*h;
Xref.Stats.Penicllin_harvested_end_of_batch = Xref.V.y(end)*Xref.P.y(end);
Xref.Stats.Penicllin_yield_total            = Xref.V.y(end)*Xref.P.y(end) - ...Penicllin_harvested_during_batch;
```

**符号必须核对**：`Fremoved` 存**负值**出流（−4000 L/h）⇒ `harvested_during_batch` 是**负数** ⇒
第三行的「减」实为**加绝对值** ⇒

```
yield_total ≡ V_end·P_end + |−Σ(Fremoved·P)·h|
```

这与 Python `simulate.py::yield_metrics`（`simulate.py:944`）的
`total = harvested_sim_g + end_in_vessel_sim_g`（其中 `harvested = −Σ(Fremoved·P)·h`）**同构**。

### 2.2 实测验证（100 批全普查）

| 检验 | 结果 |
|---|---|
| MATLAB `yield_total` 与 Python `total` 逐位同构 | **max\|Δ\| = 0.000000e+00 g**（100/100 批） |
| MATLAB `harvested_during` 恒为负（符号自洽） | 100/100 批为负，**0 批**例外 |
| 零信息对照：`Fremoved` 全置零 ⇒ `total` 退化为 `V_end·P_end` | max\|Δ\| = 0 |
| **反向验证**：若漏掉 `end_in_vessel`（只算批内放罐） | 产量口径偏差 **中位 −65.37%、最大 82.98%** ⇒ 口径选择是**实质性**的 |

### 2.3 「90 批 CSV 不含终末收获段」**不构成缺口**

100 批普查（`data/processed/batches/`）：

- **末行 `Fremoved ≠ 0` 的恰为 10 批**：`07 / 09 / 27 / 43 / 49 / 65 / 75 / 89 / 95 / 99`
  ⇒ 与 **PROBLEM.md §9**「10 批 CSV 含终末收获段（末行 Fremoved≠0），90 批不含」**完全吻合**；
- 全部 100 批的放罐段都从 **t = 100.2 h** 起（恒定）、流量恒为 **−4000 L/h**、持续 **30–90 步**（6–18 h）；
- 那 10 批的差别是**放罐段延伸到 CSV 末行**（批次在放罐中结束），**不是**「收罐后罐空」——
  两组的 `V_last` 中位几乎相同（**75.8 t** vs **76.0 t**）。

⇒ **「终末收获」是产出的后处理口径，不是需要仿真的动态过程**：
终末收获量 = **末状态的函数** `V_end·P_end`，与 CSV 里是否出现收获记录**无关**。
仿真器只需复现 ODE 轨迹 + 放罐输入（V3 已给），**无需**复现收罐这一步。

### 2.4 关闭口径（可引用）

> **end_of_batch 产量 ≡ `−Σ(Fremoved·P)·h`（批内放罐段累计）+ `V_end·P_end`（批末罐内剩余，全部收走）**
> 与 MATLAB `Penicllin_yield_total` **逐位同构**（`max|Δ| = 0.000000e+00 g`，100/100 批）。
> 「终末收获」**不是**需仿真的动态过程；90 批 CSV 不含收获段**不构成缺口**。

## 三、oq#36：MATLAB rng → numpy 映射 —— 命题证伪，关闭

oq#36 原文把这件事记作「MATLAB rng 序列 → numpy `default_rng` 映射（扰动/故障种子）」。
本轮按**四层**分别对照，结论是**四层全部不可达**，且**命题前提本身不成立**。

### 3.1 算法层：`default_rng` 与 MATLAB `twister` 不同源

| 序列 | MATLAB（MathWorks 官方文档值） | numpy `default_rng(0).random(4)` | max\|Δ\| |
|---|---|---|---|
| `rng('default'); rand(1,4)` | `[0.8147, 0.9058, 0.1270, 0.9134]` | `[0.6370, 0.2698, 0.0410, 0.0165]` | **0.896872** |

`default_rng` 是 **PCG64**，MATLAB `rng` 默认是 **Mersenne Twister**（MT19937）⇒ 不同源。

### 3.2 播种层：换成 `RandomState`（同源 MT19937）**仍不一致**

| 序列 | max\|Δ\|（对 MATLAB `rng('default')`） |
|---|---|
| `np.random.RandomState(0).rand(4)` | **0.475763** |

⇒ 即使算法同源，**播种方式也不同**（MATLAB 的 twister 播种对 32 位 seed 做数组式展开，
numpy legacy 用单值初始化）⇒ **换 `RandomState` 也不够**。

### 3.3 变换层：`randn` 的 normal transform 不同

MathWorks 官方对照表（*Random Number Streams for GPU/CPU*，R2022a）载明
**Client CPU / Twister 的 Normal Transform = `Ziggurat`**；
numpy `standard_normal` 用 **polar（Box-Muller）**。

| seed | MATLAB `rng(s,"twister"); randn(1,5)` | numpy `RandomState(s).standard_normal(5)` | max\|Δ\| |
|---|---|---|---|
| 1 | `[-0.6490, 1.1812, -0.7585, -1.1096, -0.8456]` | `[1.6243, -0.6118, -0.5282, -1.0730, 0.8654]` | **2.2733** |
| 2 | `[-0.1242, -2.5415, 0.2772, -0.1960, -0.1962]` | `[-0.4168, -0.0563, -2.1362, 1.6403, -1.7934]` | **2.4852** |
| 3 | `[0.0685, 0.9512, -0.3448, 0.0359, 1.1221]` | `[1.7886, 0.4365, 0.0965, -1.8635, -0.2774]` | **1.8994** |

⇒ 三个种子**逐点全不等**（不是重排、不是符号差）。

### 3.4 根本障碍（**不可逾越**）：种子基准本身未被记录

```matlab
% indpensim_run.m:66-73
Randomise_each_bactch = 1;
if Randomise_each_bactch == 1
    Random_seed_ref = ceil(rand*1000);   % ← 来自 rng('shuffle')，真随机、每次运行不同
else
    Random_seed_ref = 5;
end
Seed_ref = 31 + Random_seed_ref;
```

- `rng('shuffle')` 全目录共 **2 处**，均在 `fctrl_indpensim.m:195,293`（上游控制器）；
- `indpensim_run.m` 内 `rng(` 共 **19 处**、`randn(` 共 **10 处**；
- `Random_seed_ref` 取自 `ceil(rand*1000)`，而该 `rand` 来自 `rng('shuffle')` 播种的流
  ⇒ **V3 发布方未记录它** ⇒ **端到端复现 V3 的批次级随机化在原理上不可能**，
  与算法选哪个无关。

### 3.5 命题前提也不成立：Python 侧**没有**「扰动种子」这个对象

- `observe.py` 的 `np.random.default_rng(seed)`（seed=7 / 11）**只用于 EnKF 集合初始化**（估计器侧），
  与 MATLAB 的批次级参数 / 时变扰动随机化（**数据侧**）**用途完全不同**；
- Python 侧的时变扰动是**确定性渐近式**（`simulate.py:492-500`）：
  `dist(t) = asym · (1 − exp(−t/τ))`，`τ = 40 h`（对齐 MATLAB `filter(b1,a1,scale·v)` 的 EMA 均值）
  ⇒ **没有任何随机源**，也就**没有种子可映射**。

### 3.6 关闭口径（可引用）

> **oq#36 关闭为「命题证伪 + 替代口径确认」**：
> ① 四条候选路径（`default_rng` uniform / `RandomState` uniform / `RandomState` normal / 端到端）
>    **逐位对齐全部不可达**，根因分别是 **PCG64≠MT19937**、**播种方式不同**、
>    **Ziggurat≠polar**、以及**种子基准来自 `rng('shuffle')` 且未被记录**；
> ② 命题前提亦不成立：Python 侧时变扰动是**确定性代理**，**不存在「扰动种子」**；
>    `observe.py` 的 rng 属估计器侧，与 MATLAB 数据侧不同用途；
> ③ **替代口径（早已生效且有效）**：批级参数**不复现** MATLAB 随机数，而是从 V3 实测反解后**逐批登记**
>    （`golden_params.py`）；时变扰动用确定性代理。

## 四、oq#37：alpha_kla 批次间随机性 —— 量化完成

### 4.1 事实基础

- MATLAB `indpensim_run.m:135`：`alpha_kla = 85 + 10*randn;`（**批次级随机，σ=10**）；
- 引擎 `golden_params.py` 中 alpha_kla 在 86 批里 **81 批恒为 85**（从未参与标定）
  ⇒ 引擎对所有批都假设「传质系数 = 名义值」，而 V3 数据的真实值是**每批随机抽的**。

### 4.2 实验设计

12 批（黄金集 10 正常 + 2 故障）× `alpha_kla ∈ {30, 40, …, 140}`（12 档）= **144 组**，
8 进程并行，**747.9 s**。指标：产量口径偏差 `rel_err_total`、P / DO2 轨迹 relRMSE（`align="row"`，与历史一致）。

**零信息对照**：同参连跑两次 ⇒ P 轨迹须**逐位相同**（实测 `max|Δ| = 0.000e+00`，3 批）
—— 否则灵敏度测量本身不可信。

**灵敏度估计**：用**基线档邻域 ±15 的局部斜率**，不用全局线性拟合——
全局拟合会被端点崩溃档（`kla=30` ⇒ DO2 抑制 ⇒ 产量 −100%）污染，
而「σ=10 的影响」问的是**现役标定附近的一阶灵敏度**。

### 4.3 结果一：DO2 通道**强约束** alpha_kla，且反解散布 ≈ MATLAB 名义 σ

12 批中 **11 批**的 DO2 relRMSE 曲线有**内点谷**（b55 落在端点 = 曲线单调，不可反解）。
抛物线插值求谷点 `k*`：

| 批 | 8 | 11 | 16 | 22 | 23 | 27 | 36 | 55 | 60 | 80 | 91 | 92 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 现役 `alpha_kla` | 90 | 110 | 75 | 85 | 110 | 85 | 130 | 85 | 85 | 85 | 90 | 130 |
| DO2 反解 `k*` | 69.2 | 76.5 | 77.4 | 81.1 | 67.3 | 76.2 | 65.4 | *(140，端点)* | 83.9 | 79.0 | 89.8 | 94.1 |

**剔端点批后 11 批**：`mean = 78.15`、`std = **8.94**`、`极差 = 28.7`
⇒ 与 MATLAB 名义 **σ = 10** 的相对偏差仅 **10.6%**。

⇒ **判决性结论：MATLAB 端「alpha_kla = 85 + 10·randn」的批次级随机化在 V3 数据中确实生效，
且可从 DO2 通道反解出来（σ 8.94 vs 名义 10）。**
（caveat：反解是在**当前 mux/mup 逐批标定下**的最优 alpha_kla，标定会吸收一部分偏差 ⇒
σ 8.94 应视为**下界估计**，均值 78.2 低于名义 85 同向。）

### 4.4 结果二：口径决定结论 —— 产量口径 vs DO2 口径

| 口径 | σ=10 的影响（12 批） | 判读 |
|---|---|---|
| **产量** `rel_err_total` | 中位 **0.010 pp**（\|Δ/σ\| 中位 1.02e−4） | 正常批上**可忽略** |
| **DO2** `relRMSE` | 中位 **1.95%**，最大 **5.26%**（b8） | **不可忽略** |

但产量口径上存在**反向例外**（判据的反向判别力）：

| 批 | \|Δrel_err/σ\| | 现役邻域内产量跳变 |
|---|---|---|
| **b55** | **33.85 pp** | **73.9 pp @ kla=80**（80→90：−39.5% → +34.4%） |
| **b60** | **18.66 pp** | **57.4 pp @ kla=70**（70→80：−60.3% → −2.9%） |
| b91 | 0.011 pp | 33.8 pp @ kla=80 |

⇒ **alpha_kla 在本模型里是「悬崖型旋钮」**：在 9/12 批上产量对它几乎不敏感，
但在**双稳态 / 分岔批**（b55 / b60 / b91）上，**±1σ 的批次级随机性就足以跨越产量崖**
（b55 跳变 **73.9 pp**）。
⇒ 「MATLAB 的 alpha_kla 批次级随机性对复现精度的影响」这一问，**答案取决于口径与批次**，不能一句话回答。

### 4.5 结果三：「统一用名义 85」在 DO2 口径上系统性失配

`|k* − 现役 alpha_kla|`：**6/12 批 > 20**（b8:21 / b11:34 / b23:43 / b36:65 / b55:55 / b92:36），
中位 **21**。

### 4.6 结果四：DO2 拟合最优 **≠** 产量口径最优

4 批两者相差 > 30：b8（DO2 69 vs 产量 100）、b16（77 vs 110）、b22（81 vs 140）、b55（**140 vs 90**）
⇒ **不能用 DO2 通道单独标定 alpha_kla**（b55 最极端：DO2 偏好一路加大到 140，而产量在 90 就跨崖）。

### 4.7 关闭口径（可引用）

> **oq#37 关闭**（量化完成）：
> ① **MATLAB 名义 σ=10 的批次级随机化在数据中生效**，DO2 通道反解 `k*` 散布 **σ = 8.94**（名义 10，偏差 10.6%）；
> ② **产量口径**：9/12 批 σ=10 影响 < 0.4 pp（可忽略），但**双稳态批**（b55/b60/b91）上达 **18.7–33.9 pp**
>    且邻域内产量跳变 **33.8–73.9 pp** ⇒ **alpha_kla 在这些批上是产量崖旋钮**；
> ③ **DO2 口径**：σ=10 影响中位 **1.95% relRMSE**（最大 5.26%）⇒ 不可忽略；
> ④ **统一用名义 85 失配**：6/12 批 \|k*−base\| > 20；
> ⑤ **DO2 拟合最优 ≠ 产量口径最优** ⇒ 不能用 DO2 单独标定 alpha_kla。

### 7.1 顺带修掉的一个既有缺陷：治理脚本的**行尾双重 CR**

排查本轮写入时发现：**R161 及更早的治理脚本**用 `text.replace("\n", nl)` 写回，
当文件本身已是 CRLF 时会把 `\r\n` 变成 **`\r\r\n`**（**每个行尾多一个 CR**）。
污染范围：`ENGINE_CONTRACT.md` **1012 处**、`state.yaml` **296 处**。

- 修法：治理脚本的 `write()` / `normalize_eol()` 先把行尾**归一为 `\n`**再转目标风格，
  并对 `\r\r\n` **优先**处理（否则 `\r\r\n` → `\r\n` → `\n\n` 会**把一行拆成两行**，
  本轮首版修复正是踩了这个坑，靠 `runs/_r162_backup/` 备份回滚后重做）；
- 本轮已把两个文件**归一化为纯 CRLF**（无重复 CR），`state.yaml` YAML 复验可解析；
- 所有 md 文件（台账 / 签核单 / 路线图 / README / 工具索引 / 报告 / 记忆）实测 **crcrlf = 0**。

⇒ 该缺陷属 **D-77 同型的文档卫生问题**，本轮一并修复；**未单独立债**（已当场闭合且可机器复验）。

> 本条是 §5.1 所列三个治理脚本缺陷中的第 1 个，另两个（版本行插行中 / 记忆章节静默不写）见 §5.1。
