## 1. 裁决前的核心判断：为什么「直接改默认引擎 + 重算基线」不是最优解

§8.7 (b) 为四项执行项写的路径是「改引擎 ⇒ 重跑 86 批 ⇒ **建立新基线**」。经复核，这条路径在
本项目当前证据状态下**不是最优**，甚至会损害目标本身。四条实证理由：

| # | 理由 | 证据 |
|---|---|---|
| 1 | **回归锚不可再生** | 86 批 `max\|Δ\| = 0.00e+00` 是唯一能证明「引擎未被悄悄改坏」的逐位锚。重算基线后，新基线本身包含改动，无法再区分「改进」与「回归」；GOAL §4 第 1 条的 ±5% 验收也随之失去可复现基准 |
| 2 | **V2 的逐位复现原理上不可达** | R162 `oq#36` 已证：MATLAB `rng('shuffle')` 种子未记录、PCG64≠MT19937、Ziggurat≠polar ⇒ 四条候选路径逐位对齐全部不可达。回填随机成分只能做**统计等价方差注入**，把「可复现的近似」变成「不可复现的近似」，且**没有 MATLAB 逐批种子做对照** ⇒ 无法证明「更接近 MATLAB」 |
| 3 | **V1 的全局阈值 10 会让判据恒假** | `runs/r163_innovation_calibration.json` 20 批实测：`CO2outgas` 跨批 `max\|z\|` 的 p90 = 5.56、**最大仅 7.60**；`O2` 最大 0.167（`0/20` 批越 5）。全局改 `z>10` ⇒ CO2 通道**永不触发**；枚举中 `z>15` 起所有候选组合一律 `0/20` 触发 ⇒ 正向判别力归零，违反 D-78「禁止恒真/恒假判据」 |
| 4 | **V3 存在产量崖** | `golden_params.COMBINED` 88 批中 **81 批 `alpha_kla = 85`**（零回归正是走它）；R162 `oq#37` 实测双稳态批 b55/b60/b91 在现役邻域内产量跳变 **73.9 / 57.4 / 33.8 pp**。无差别写回 81 批会同时改动产量与 DO2 口径，且无法归因是「标定改善」还是「崖上跳变」 |

**结论**：最优解不是「批准并直接改默认」，也不是「拒绝推进」，而是把五项全部推进到**可验证、可回滚、可比较**的状态 ——
即下面的四层架构。这既满足「最优目标」（拿到真实改进证据），又保住长期硬基线。

## 2. 最优架构：冻结基线 + opt-in 候选通道 + 证据闸门

```
L0 冻结基线（默认路径，逐字不变）
   └─ 86 批逐位零回归锚永久保留；GOAL §4 ±5% 验收仍以它为准
        │
L1 opt-in 候选通道（本轮新建，全部默认关闭 / 种子或参数可控 / 可完全旁路）
   ├─ V1  innovation_criteria：逐通道阈值 + 持续占比（否决「全局 5→10」）
   ├─ V2  dist_noise：8 路统计等价方差注入（不宣称 MATLAB 复现）
   └─ V3  alpha_kla_source：仅 11 批双约束可标定值，排除产量崖批
        │
L2 证据闸门（tools/r166_ab_gate.py，D-78 合规）
   ├─ 零信息对照（健康批无故障）
   ├─ 双向判据（正向触发 + 反向判别力，禁恒真/恒假）
   ├─ 数据驱动阈值（扫描 + 显式裕度准则 + LOO），不得手写或事后放宽
   └─ A/B 量化：候选 vs 冻结基线，逐项给出 Go / No-Go 实值
        │
L3 切换决策（**下一阶段，本轮不执行**）
   └─ 仅当候选在 L2 证据上严格优于冻结基线，经用户二次确认后
      才考虑切换默认并走「基线更新流程」；本轮绝不自动切换
```

**为什么不直接切换默认**：切换 = 承认新行为是生产口径，需要独立的用户确认与独立的基线冻结流程；
把它塞进治理轮里「顺手」做，正是 §8.7 (d) 边界声明所禁止的。

## 4. 判据纪律（承 D-78 / 纪律 30 / 31 / 32）

1. 任何新判据必须做**零信息对照**（健康批、无故障注入）；
2. 判据必须**双向**：正向触发率 + 反向判别力，缺一不可；**禁止恒真 / 恒假**；
3. 阈值必须由**数据驱动扫描 + 显式裕度准则 + LOO** 确定，不得手写、不得事后放宽；
4. 「不可辨识」与「不可验证」分层证明，机制表述先核对源码（纪律 32）；
5. 纯文本子串 `grep -c` 不得作判据；数字一律从 `runs/` 产物读取；
6. 多轮寻优仍无法解决时**诚实降级**（本轮 V2 即属此类），不得粉饰、不得偷放宽阈值。

## 8. R166 执行补记：V2 多轮寻优与诚实降级（2026-11-06）

> 本节记录**裁决后的实测结果**，不改写 §1–§7 的任何裁决口径；数字来自
> `runs/r166_v2_optim.json`、`runs/r166_ab_gate_first_pass.json`（首轮原始证据留档）。

**首轮实测**：按 `runs/r163_dist_variance.json` 的 8 路 `analytic_sigma` 全幅注入
（scale = 1.0），6 批中 3 批触发灾难性产量崩塌（|Δ| ≥ 30 pp），最大
**96.0588 pp**；固定种子 6/6 可复现。`runs/r166_ab_gate.json` 首轮 V2-3 / V2-4 FAIL。
这是**真实物理结果**，不是脚本缺陷。已留档为 `runs/r166_ab_gate_first_pass.json`。

**多轮寻优**（`tools/r166_v2_optim.py`，只改被评测的注入设计，V2-3 上界 20 pp /
V2-4 上界 30 pp **一字未改**）：

| 轮 | 动作 | 结果 |
|---|---|---|
| 1 | σ = 0 零信息对照 | 与冻结路径逐位一致 |
| 2 | scale = 1.0 全幅复现 | 3 批崩塌，max|Δ| = 96.0588 pp |
| 3 | scale 网格 {0.02, 0.05, 0.10, 0.20, 0.35, 0.60, 1.00} × 6 批 | 逐批 Δ 全量记录 |
| 4 | 显式目标 rms(Δ) 距 R163 实测 3.0879 pp 最近 | 5 个可行 scale，seed=7 下最优 0.35（rms 2.1322 pp）；按批 LOO 重选一致 |
| 5 | 额外种子 11 / 23 样本外 | **seed=11 在同一 scale 下仍致 2 批崩塌，max|Δ| = 99.8524 pp**；seed=23 无崩塌 |

**结论：V2 诚实降级为 No-Go。** 崩塌不是 σ 幅值的单调函数，而是双稳态批对扰动
**实现路径（种子）**的敏感依赖；用单一种子「恰好不崩」的 scale 属过拟合，正是 D-78
禁止的恒真 / 事后放宽。因此：

- V2 保持 `opt-in`、默认关闭、**不切默认生产路径**；`runs/r166_ab_gate.json` 保留
  V2-3 / V2-4 原始 FAIL，不删除、不改写为 PASS，总判定按 D-78 合规证据升格为 `NO_GO`。
- 全幅 σ 与多种子崩塌实值登记为债务证据，根因治理转 `docs/roadmap_next.md` §8.8
  **R166-9**（逐通道消融 + 双稳态阈值穿越核查）。
- 其余四项裁决口径、§5 红线、L3 切换决策需用户二次确认等**均不变**。
