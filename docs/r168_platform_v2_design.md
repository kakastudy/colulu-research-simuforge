## 一、为什么重设计：把「看板」改回「计算平台」

用户对当前 `platform/` 的判断是准确的：

> 「不是研发成果的看板，而是一个基于研发好的算子/求解器等，构建青霉素反应罐的仿真引擎，并可进行仿真计算。」

### 1.1 现状体检（实测，非观感）

| 维度 | `platform/`（R167，冻结） | 证据 |
|---|---|---|
| 视图构成 | 6 视图：回归总览 / 过程拓扑 / 批次工作台 / 通道诊断 / 算子库 / 观察·控制工作台 | `platform/index.html` |
| 其中「做计算」的 | **1.5 个**（批次工作台的参数试算 + 工作台的通用调用表单） | — |
| 其中「看成果」的 | **4.5 个**（86 批回归、通道健康矩阵、拓扑、算子目录、证据面板） | — |
| 可调参数 | **14 个**（`ALLOWED_OVERRIDES` 白名单） | `platform/serve.py:65` |
| 引擎实际支持 | **75 个**（`params.get` + `if k in params` 两类装配口） | AST 提取 `simulate.py` |
| 输出通道 | 8 个（S/P/X/PAA/DO2/OUR/vis/CER） | `platform/serve.py:60` |
| 引擎输出通道 | **41 个**（含 A0/A1/A3/A4 菌丝区、CO2d、pH_openloop、mux/mup 等） | `simulate.py` 返回列 |
| 轨迹分辨率 | 2 h 下采样 | `platform/serve.py:62` |
| 引擎原生 | 0.2 h（1149 步） | `simulate.py` |
| 交互模型 | 同步阻塞，单次 18–84 s | 实测 |

**结论**：引擎侧的能力（A/B/C/D 四档、故障注入、扰动、闭环、有效域、寻优）早已研发完毕，
但平台只把它们放在「一张可点开的清单」里。平台没有把引擎**当成计算设备**来用。

### 1.2 平台 v2 的定位

| | `platform/`（旧） | `platform_v2/`（新） |
|---|---|---|
| 回答的问题 | 「这轮研发做得怎么样」 | 「给我一个工况，引擎算出什么」 |
| 主视图 | 回归总览（86 批误差散点） | **仿真台**（配工况 → 跑 → 读轨迹） |
| 数据来源 | `data.js` 预烘焙 1.1 MB 静态包 | **服务端实时调用引擎**，前端零预烘焙 |
| 参数面 | 14 键白名单 | **97 键**（AST 派生） |
| 通道 | 8 | **40** |
| 分辨率 | 2 h | **0.2 h 原生**（可选 3/6/12× 抽稀） |
| 交互 | 同步阻塞 | **异步作业队列**（进度可见 / 可取消 / 结果缓存） |

## 二、关键设计决策

### 2.1 决策一：参数表从引擎源码**派生**，不手写

**问题**：R167 已经吃过一次亏 —— `ops_registry.OPERATORS` 里 `hier_est` 不是可调用函数、
`conservation_metrics` 是模块名不是函数名，两者都被「文件存在 ⇒ 已装载」掩盖。
本项目的历史教训（D-38 / D-65 / R152）反复是同一类：**「清单说的」与「代码真的做的」分叉**。

**处置**：`platform_v2/param_catalog.py` 用 **AST 解析** `simulate.py`，
提取引擎真正接受的参数键。源码改了，参数表自动跟着改；源码里没有的，平台就调不到。

**派生的两个装配口**（首版只覆盖了第一个，自检立刻抓出漏项）：

```
① params.get("key", default)              —— 直读式
② if "key" in params: par[i] = params["key"]  —— 索引装配式（写进 105 维参数向量）
```

> **首版教训**：只匹配第 ① 类 ⇒ 18 个动力学键（m_s / q_co2 / gamma1 / Y_NX …）被误判
> 「源码已移除」。自检（`unknown`/`missing` 两项必须为空）当场抓到。
> ⇒ 这条自检现在是闸门 G2b/G2c 的常驻判据。

### 2.2 决策二：工况开放度 = 全开 + L3 五键硬拒绝

开放 97 键，覆盖动力学 / 形态学 / 故障注入 / 时变扰动 / 操作与控制 / 数值积分器 / 初值 / pH 通道 / 软测量九组。
L3 五键（`dist_noise_sigma`、`dist_noise_seed`、`innovation_criteria`、`k_dual`、`alpha_kla_override`）
按 R166 裁决**保持 opt-in**，平台侧硬拒绝（HTTP 400，见 §2.4）。

### 2.3 决策三：新增量程校验（`[low, high]` 越域即拒）

**问题**：`mux=1e308` 是**有限数**，能通过 NaN/Inf 检查。若放行，引擎会跑出一个看似正常的轨迹
—— 这是最坏的一类失败（「恒真的判据等于没有判据」的近亲：失败不可见）。

**处置**：参数表登记**已知有效域**（不是物理上下限），越域直接拒绝提交并报出具体区间。

### 2.4 决策四：校验**前置到提交时**，不拖到后台

R168 闸门首轮 G3/G7 **全部返回 200** —— 因为参数校验发生在后台线程里，
前端拿到的是「提交成功」，几分钟后才看到失败信息，无效作业还会占满队列。

**处置**：`submit_sim()` 在入队前先调 `assemble_params()`，校验不过直接 HTTP 400。

### 2.5 决策五：异步作业队列（同步阻塞不可行）

单次仿真 18–84 s。同步 HTTP 会超时、阻塞其它请求、且用户无法区分「在算」与「卡住了」。

```
POST /api2/run   → 立即返回 job_id
GET  /api2/job/<id>?full=1 → queued / running / done / failed + 进度
```

- **仿真串行、接口并行**：引擎是 CPU 密集 + GIL 争用，并发不提速反拖慢 ⇒ 队列串行，
  但 HTTP 层多线程（一个慢仿真不阻塞 health / catalog 查询）。
- **结果缓存**：同工况指纹 ⇒ 命中缓存直接返回（省算力 + 保证可复现）。
- **可取消**、**有界**（排队上限 8）。

### 2.6 决策六：旧平台**原样冻结**，不动一行

R167 已把 `platform/` 冻结为契约 v1.97 + 闸门 25/25 + 86 批逐位零回归锚。
本轮**新增** `platform_v2/`，独立端口 **8772**；8770 不重启、不触碰。

> 用户裁决即「新建 platform_v2/，旧平台原样冻结」。

## 四·B、R168.1 交互重构（第二轮：UI 反馈驱动）

第一版的仿真台把 40 个通道塞进**一个 SVG 里纵向堆叠**，通道一多就变成一条长条，
量纲不同的曲线共用一根时间轴，读者必须靠颜色猜哪条是谁。本轮按实际使用反馈重做。

### B.1 轨迹图：每通道一张独立卡片

| 改动 | 前 | 后 |
|---|---|---|
| 图的粒度 | 1 个 SVG，内含 N 个子面板 | **N 张卡片**，每张一个通道 |
| 图例 | 全局一个（只在底部写"虚线=实测"） | **每张卡片自带图例**（实线=仿真 / 虚线=实测） |
| 纵轴 | 各自量程但共用画布 | 每张卡片独立 y 轴 + 刻度 + 单位 |
| 读数 | 只能看曲线形状 | 卡片头部直接给 **末值 · 峰值** |
| 网格 | `minmax(330px, 1fr)` 自适应 | 同左，窄屏自动降列 |

**为什么每通道独立而不是叠图**：产物 P（g/L）、生物量 X（g/L）、残糖 S（g/L）
虽然量纲相同，但 pH、DO2、T、V 完全不在一个尺度上。叠在一张图里必然要归一化，
而归一化会**抹掉量纲差异**——这正是 R151 提"产量指标对 P 轨迹失明"时想避免的问题。
拆开后，每张图的 y 轴刻度就是真实单位，不需要任何归一化说明。

### B.2 通道选择器：分组 + 全选/取消全选/反选

40 个通道逐个点不现实。改为：

- 顶部工具条：**全选 N / 取消全选 / 反选** + 「已选 X / N」实时计数
- 六个分组（状态量 / 气体与代谢 / 菌丝区 / 动力学 / 诊断 / 操作量）**默认折叠**，
  每行显示「已选/总数」，组内另有 **全选 / 取消**
- 展开组才列出该组通道的 chip（带颜色色块 + 引擎键名）

折叠是必要的：40 个 chip 全展开要占 300px 纵向空间，把图表挤到屏幕外。
折叠后只占 6 行 ≈ 130px。

### B.3 诊断区：并列面板 → Tab 切换

「形状指标 / 守恒与守卫审计 / 生效参数」三块原本纵向并列，结果区被拉到很长。
改为单个面板内 **4 个 Tab**：形状指标 / 守恒与守卫审计 / 生效参数 / **轨迹级指标**（新增）。
每个 Tab 角标显示真实条目数（不是占位符）。

### B.4 扫描：修两个真 bug

#### bug ①：二维响应曲面**一个格子都没画**（用户报"运算结束是空的"）

```js
// 错：轴坐标在 p.x 里，p.y 是「响应值」（标量）
const yi = ya.values.findIndex((v) => Math.abs(v - p.y[ya.key]) < 1e-9);
//   ⇒ p.y[ya.key] 恒 undefined ⇒ Math.abs(v - undefined) = NaN ⇒ NaN < 1e-9 为 false
//   ⇒ findIndex 恒返回 -1 ⇒ 9 个点全部被 `if (xi < 0 || yi < 0) return;` 跳过
//   ⇒ 响应曲面一个格子都没画，界面表现为「空的」
```

实测证据（二维 3×3 扫描）：后端返回 **9/9 点成功、y 值齐全**，
但浏览器里 `rect.heat-cell` 数量 = **0**，SVG 只有 7 个子元素（坐标轴与标题）。
修复后同一场景 `heat-cell` = 4（2×2）、表格 4 行。

**这个 bug 之所以能活下来**：上一轮复验只断言了"svg 存在"，
没断言"数据标记数 > 0"。现已把断言改成 `heat_cells >= 4`，
**断言数据而不是断言容器**——否则下一个"画了个空壳"的 bug 还会漏网。

#### bug ②：一维响应曲线的 x 坐标错位

```js
const order = pts.map((p, i) => i).filter((i) => pts[i].y !== null);
const d = pathFrom(order.map((i) => xs[order.indexOf(i)]), ...);
//                ^^^^^^^^^^^^^^^^ order.indexOf(i) 是 i 在 order 里的「位置」，不是 i 本身
```

全部点成功时 `order = [0,1,2,…]`，`indexOf(i) === i`，**恰好正确**；
一旦有点失败，`order` 变成 `[0,2,…]`，x 值整体错位 ⇒ 折线画在错误的位置上。
已改为按原始下标取 `xs[i]`。

#### 附：全失败场景不再显示空坐标系

参数越域（如 `mux=2.0` 超出有效域 `[0.10, 0.80]`）会让**所有**扫描点失败。
旧行为：画一张只有坐标轴和红叉的空图 —— 观感就是"运算结束是空的"。
新行为：

1. 顶部统计条显式写「**成功 0/4 · 失败 4**」（成功数与失败数分色）
2. 不画坐标轴，改为**失败原因清单**：每行 `mux=2.0000 · mup=0.0380 → 工况参数被拒绝 [param_invalid]`
3. 明细表同步标注「失败」

失败点始终**不参与 min/max 统计**，也**绝不被渲染成 0 值**（R168 原设计约束不变）。

### B.5 顺手修掉的横向溢出

抽屉用 `transform: translateX(100%)` 移出屏外，但 **transform 会计入文档滚动区域**：
`documentElement.scrollWidth = 2160`（视口 1600）⇒ 页面能横向拖 560px，
把屏外的抽屉拖出来，界面出现一个半透明的"详情"面板。

修法：`html, body { overflow-x: hidden }` + 抽屉改 `position: fixed`（视口锚定，
不计入文档横向滚动区域）+ `visibility: hidden`（关闭时彻底不可见）。
实测 `scrollWidth` 2160 → 1600，`scrollLeft` 恒为 0。

## 四·C、R168.2 第三轮：折叠、时间条、扫描的意义与数据

### C.1 状态轨迹选项面板可折叠

选项面板（全选/分组/40 个 chip）常驻约 227px，结果页多数时间不需要它。
面板头加「选项 ▾ / 收起 ▴」开关：**默认收起**，头部保留「N / 总 通道」计数与
仅仿真/叠加实测切换，收起不丢信息；展开态写入 localStorage（`ferm-picker-v2`），
下次进页保持。组内折叠逻辑不变（`chGrpOpen`）。

### C.2 运行仿真的时间条

引擎不回报积分进度（`solve_ivp` 内部无回调），**真百分比不可得** ——
做一个假百分比才是骗人。实现为「时间条」：

- 提交成功即显示：`已用 Xs · 预计 ~Ys`；
- **预计时长自适应学习**：完成后把实际耗时写进 localStorage（按 stride 分键
  `ferm-exp-<stride>`），下次同分辨率用真实历史值；无历史时默认 48s（全量）/ 28s（抽稀 12×）；
- 条宽 = min(95%, 已用/预计)，**到 95% 封顶**；超时后文案改为
  「较预期慢（首次算该工况属正常）」、标签转 warn —— 不撒谎到 100%；
- 缓存命中（elapsed < 5s）不学习，避免把 0 秒学成预计时长。

### C.3 扫描部分：把「意义」写进界面，把「数据」全部亮出来

**意义何在**（左栏新增解释面板，引项目实测结论）：
① 敏感性排序 —— 平坦参数不值得调；② 可行域边界 —— 阈值型悬崖 vs 平滑过渡
决定工艺容差（Fs < ±1%、γ1@0.985 悬崖都是扫出来的）；③ 参数耦合 —— 二维网格看交互；
④ **失败点即边界** —— 失败带本身就是可行域边界的证据。

**数据展现增强**（后端 `scan.py` 一直带回 yield_err / co2d_max / ph_min / health，
此前前端只展示了主响应）：

| 增强 | 实现 |
|---|---|
| 响应量逐项说明 | 10 个响应量各配一句"这项响应告诉你什么"（如 yield_err ↔ ±5% 红线） |
| 统计条加波动 | `Δ = y_max − y_min` + 相对中位的百分比 —— 敏感性一目了然 |
| **形态判定（一维）** | 最大局部斜率 / 全程平均斜率 ≥ 3 ⇒ **阈值型**（红），否则平滑型（绿）；阈值型在图上标出**陡变段 x 位置** —— 可行域边界的坐标 |
| 健康分级着色 | 成功点/格按 normal/benign→accent、degraded→warn、catastrophic→crit 着色，安全区在图上直接分层 |
| 极值点标注 | yield_err/health 取 \|y\| 最小（"最优"），其余取最大（"峰值"）：一维画圆环+数值，二维画绿框 |
| 明细表加三列 | 产量误差% / CO2d 峰 / pH 最低（每点真实计算值，非推断） |
| 导出 CSV | 全字段带 BOM 导出（Excel 直开）—— 一次扫描几十分钟，数据必须能带走 |

|---|---|

## 四·D、R168.3 第四轮：运算结果留存、执行时间与可重算

### D.1 问题不是"缓存不够大"，是"结果根本没落盘"

用户的诉求是「历次执行仿真运算的结果存一份，不用每次重新算，还要能看到执行运算的时间，同时也能重新执行」。
体检结论：v2 此前的结果**只在进程内存**里 ——

| 层 | 位置 | 生命周期 | 能否满足"历次留存" |
|---|---|---|---|
| `JobManager._jobs` | 内存 `OrderedDict`，`MAX_JOBS_KEPT=60` | 服务重启即清空 | 否 |
| `JobManager._cache` | 内存 `OrderedDict`，`CACHE_MAX=24` | 服务重启即清空 | 否 |
| 服务日志 | `runs/*.log` | 无结构化结果体 | 否 |

所以不是"加个缓存开关"，必须新增一层**磁盘留痕**，且存的要够回放整张结果页（40 通道轨迹 + 全部指标），
不能只存摘要 —— 否则点开历史还得重算，诉求就落空了。

### D.2 三种动作必须语义分明

这是本轮最容易做错的地方：把"看历史"做成"再算一次"，或者把"重新计算"做成"命中缓存秒回"，都是假的。

| 动作 | 入口 | 服务端 | 是否新增留痕 |
|---|---|---|---|
| **运行仿真** | 顶栏主按钮 | `POST /api2/run`，按工况指纹查缓存 | 命中缓存 ⇒ **不新增**（没算过就不是"一次运算"）；真算过 ⇒ 新增 |
| **查看结果（回放）** | 历史卡片「查看结果」/ 卡片空白处 | `GET /api2/history/<id>?full=1` | **不新增**，且不调用引擎，**零计算** |
| **重新计算** | 顶栏「重新计算」/ 来源条 / 卡片「重算」 | `POST /api2/run {force:true, rerun_of}` | **必新增**，`use_cache=False` 强制真算 |

`force` 绕过的是"查缓存"，算完仍写回缓存 —— 下次普通运行照样秒回。
新记录带 `rerun_of` 指向来源记录，形成可追溯的重算链。

### D.3 落盘格式（`platform_v2/history.py`）

```
runs/sim_history/
├── index.json                       摘要索引（倒序、最新在前，不含大结果体）
└── sim-20261109-114354-6eb93a.json  单条完整记录
```

| 字段 | 说明 |
|---|---|
| `created_at` / `started_at` / `finished_at` | **执行运算的时间**（ISO 本地时间带时区），列表主显示 |
| `elapsed_s` | 真实耗时（缓存命中不记） |
| `batch` / `stride` / `overrides` / `fingerprint` | 完整工况，点开历史会**回填到左栏**，重算才确实用的是那次参数 |
| `state` / `code` / `error` / `has_result` | 失败也留痕（发散 / 越域是可行域边界证据），但不可回放 |
| `summary` | 误差 / 健康分级 / 通道数 / 步数 / 告警，卡片不必打开大文件 |
| `result` | **完整结果体**（40 通道轨迹 + 形状 / 守恒 / 生效参数），回放零计算 |

工程细节：临时文件 + `os.replace` 原子写、线程锁保护索引、`MAX_RECORDS=120` FIFO 淘汰、
索引损坏时扫描目录重建（不删用户数据）、id 正则白名单防目录穿越、NaN/Inf 清洗为 `null`。
`PENOPS_SIM_HISTORY_DIR` 可覆盖目录，闸门用它做隔离测试。

### D.4 接口与前端

| 接口 | 用途 |
|---|---|
| `GET /api2/history` | 摘要列表（含 `n`、目录） |
| `GET /api2/history/<id>?full=1` | 完整记录（回放） |
| `DELETE /api2/history/<id>` | 删除一条留痕 |
| `POST /api2/run {force, rerun_of}` | 强制重算 + 标注重算来源 |
| `GET /api2/health` | 新增 `history_n` |

前端在仿真台顶部加**全宽「运算历史」面板**（可折叠、状态记忆）：卡片显示执行时间、批次、抽稀倍数、
覆盖项数、耗时、误差与健康分级、重算来源；`查看结果` / `重算` / `删除` 三个动作。
结果区顶部加**来源条**，明确标注「历史回放 / 复用缓存 / 本次运算已留痕」+ 执行时间，
杜绝"几份结果摆在一起分不清哪次"的问题。

### D.5 实测证据（端到端探针，非静态推断）

```
首次运算   done 61.17s  → history_id=sim-20261109-114354-6eb93a

跨进程读盘 另一个 Python 解释器直接读 JSON → True, 40 通道
二次提交   from_cache=True, phase=cached, 历史条数不变（2 → 2）
force 重算 done 48.29s, phase=done（非 cached）→ 历史 2 → 3
新记录     rerun_of=sim-20261109-114354-6eb93a, force=True, created_at=11:44:43
结论       PASS
```

**服务真实重启实证**：停掉 8772 进程 → 重新拉起 → `health.history_n` **8 → 8**
（内存 `_jobs` / `_cache` 已全部清空，历史只可能来自磁盘）；页面仍列出 6 张卡片，
最新执行时间 `2026-11-09 12:04:08`；点开回放得到 4 张 KPI + 3 张轨迹卡片、来源条「历史回放」，
0 console error。这一条比任何静态断言都更直接地回答了用户的诉求。

### D.7 本轮踩的三个前端坑（静态检查全都抓不到）

| 坑 | 现象 | 修法 / 教训 |
|---|---|---|
| **TDZ** | 把 `runSim` 从函数声明改成 `const` 箭头函数，而顶栏事件绑定在它初始化**之前**执行 ⇒ 页面加载即 `pageerror: Cannot access 'runSim' before initialization`，整页脚本停摆、参数面板空白 | 改回 `function` 声明（可提升）。**`node --check` 只查语法，查不出 TDZ** —— 每次改前端必须先做 10 秒浏览器冒烟，再跑几分钟的逐屏复验 |
| **`[hidden]` 被作者样式覆盖** | `.btn { display:inline-flex }` 优先级高于 UA 的 `[hidden]{display:none}` ⇒ 本该隐藏的「显示全部」按钮一直挂在面板头 | 全局 `[hidden] { display:none !important }`。项目里 `.tabpane[hidden]` 早就单独打过补丁，说明这是老问题的另一个实例 |
| **复验脚本静默失效** | R168.1 起通道分组默认折叠 ⇒ chip 不在 DOM ⇒ 脚本里"恢复 3 个通道"一个都没点到，`state.traceCh` 一直是空；回放历史时结果页显示「未选择任何通道」，看起来像"又没出图" | 双修：① 前端在**展示任何一份新结果**（实时/回放）且零选中时恢复默认 P/X/S，避免用户误判；② 复验脚本先展开各分组再点 chip，并把 `restored ≥1` 纳入判据，杜绝静默失效 |

> 第三条尤其值得记：一个"没点到"的复验步骤可以连续几轮全绿，直到某条**新断言**
> （回放要有轨迹卡片）才把它逼出来。**复验脚本自己也要过闸** —— 和 G9 规则自验证同理。

### G9 静态规则本身也要过闸（自验证）

G9a/G9b 是把已修的真 bug 固化成前端静态规则（对 `app_v2.js` 剥离注释后正则扫描）。
规则写完立刻用 `tools/r168_platform_v2_gate_selfcheck.py` 自验证：当前代码必须 0 命中、
注入旧 bug 必须报警、注释/字符串里的写法必须不误报。第一版自验证 **6/8 FAIL** ——
规则无效，暴露了三层坑（每层都修掉并加为回归用例）：

1. **正则字面量里的引号**（实战触发点）：`replace(/[&<>"]/g, c => ({'"': "&quot;"}[c]))`
   —— 初版扫描器把正则里的 `"` 当字符串开头，`'"'` 的 `'` 又当另一段字符串开头，
   整个文件后半段被吞进"字符串" ⇒ `//` 注释不再剥离 ⇒ 注释里的错误写法被误报成代码。
2. **标识符丢失**：重写扫描器时标识符只进了关键字判定缓冲、忘了写回输出 ⇒
   注入的真实 bug 代码被"吃掉" ⇒ 该报警的反而不报（比误报更隐蔽）。
3. **字符串内容残留**：字符串/模板文本/正则体的内容必须替换为空（保留换行维持行号），
   否则字符串里的错误写法会被误报。

最终自验证 **11/11 PASS**（含正则引号、模板插值、除号误判三条回归）。
R168.3 收尾时全量闸门 **36/36 PASS**、逐屏复验 **12 项全过**（0 console error / 0 个 4xx）。

> 方法论补充：**闸门规则要先过自己的闸**。一条会误报的规则比没有规则更坏 ——
> 它会让下一次真警报被当成狼来了。

## 七、已知限制

1. **单点仿真 18–84 s** ⇒ 一次二维扫描（16 点）需 5–20 分钟。已用异步队列 + 进度 + 取消缓解，
   但**不是**交互式的快速响应。
2. **`data.js` 未预烘焙**：旧平台的静态数据包在 `platform/` 里仍在用；v2 不依赖它。
3. **菌丝区通道（A0/A1/A3/A4）已暴露**，但按 R166/V5 裁决它们**结构不可辨识**
   （`H_assim` rank=0 / nullity=4）⇒ 平台可显示，但**不可作交付宣称**。
4. **形状指标与轨迹指标口径不同**（前者按 `time_h` 对齐，后者按行号采）⇒ 两者并排展示，不互相替代。
5. **通道全选 40 个 ⇒ 40 张卡片**，结果页会很长（约 40 × 190px）。这是刻意的：
   通道一多就该逐个看，不该挤在一张图里。用分组全选/取消控制范围。
6. **二维扫描的网格点上限 16**（4×4）；超过时按 `linspace` 均匀抽稀并保留首尾。
   抽稀后曲面是**子采样**，不是全网格 —— 面板上的点号 `已扫 N/16` 是实际计算量。
7. **运算历史上限 120 条**，超限按 FIFO 淘汰最旧的记录文件（单条完整结果约 60 KB，
   上限约 7 MB）。这是刻意的：留痕是工作台便利，不是长期归档 / 数据库。
8. **只有仿真台的单次运算留痕**：参数扫描是批量试算，不留痕（其逐点数据可导出 CSV）；
   命中缓存的秒回也不留痕 —— 没执行运算就不算"一次运算"。失败作业留痕但不可回放。
